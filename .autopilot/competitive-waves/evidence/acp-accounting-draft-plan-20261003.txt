1. Freeze contract and leaf types first (surge-core + surge-acp)
Add an accounting module in core with validated PhysicalTurnId, AccountingScope
(TaskAttempt binding or explicit Auxiliary operation), immutable prepared-turn
context, SourceContractId/version, UsageReceiptV1, independent u64 reported total,
input/output/thought/cache-read/cache-write fields, and per-field presence/validity.
Do not derive Deserialize around constructor invariants without try_from checks.
Receipt includes actual opening/writer occurrence, host/provider session identity,
physical-turn sequence, stop/outcome, adapter artifact/version evidence, nullable
model and explicit measurement extent. Unknown, per-turn, session-cumulative and
reported-processing-window are distinct contracts. Claude 0.23.1 is the last of
these, not a claim of all work attributable only to the triggering request.
No guessed subset sums: reported total is independent, bucket overlap rules must
come from the contract. Zero, missing, malformed and unsupported are distinct.

Add surge-acp bridge/usage_contract.rs registry keyed by runtime adapter artifact,
version and protocol feature/schema. Establish identity once during launch and
initialize, tied to the actual launched artifact, not npx cache/discovery version.
Prefer resolved/pinned absolute executable or package artifact plus content digest,
captured launch descriptor and matching initialize implementation identity.
An unpinned launcher or unsupported/unproved version selects Unknown and retains
observations without normalizing them. Protocol V1 alone never selects semantics.
Provider claims are observations, not authentication of vendor identity. Recheck
artifact continuity on reopening; no probing subprocess per prompt. Preserve the
existing launch hash/fencing behavior; add evidence rather than repurpose it.

2. Make the physical RPC boundary durable and completion reliable
Add a persisted prepared physical turn and one-use BeginPhysicalTurn operation to
the run writer. Stage code prepares a fresh id before each initial/feedback call;
worker claims it through an injected object-safe accounting sink after existing
effect admission and BEFORE polling connection.prompt. The durable claim binds
run, exact StageEntered/invocation, opening, source and task binding. Await storage;
failure means zero RPC. Reusing a claimed id never repeats an RPC after restart;
ambiguous claim-before-wire crash remains unobserved, not automatically replayed.
Bridge/acp_bridge.rs, facade.rs, command.rs, lifecycle.rs and worker.rs carry the
prepared context and typed completion receipt. Core owns data; ACP owns protocol
capture and an injected sink trait; orchestrator implements the sink using the
RunWriter handle, avoiding ACP -> persistence dependency.

The worker commits the completion/usage before replying, even if the caller's
oneshot is dropped. Lifecycle owns the prompt task through bounded cancellation;
close must drain/account the response before dropping IO. Provider cancelled
response may still contain valid usage: persist it before expressing cancellation
as execution failure. Transport error, timeout, task panic, host death or missing
receipt leaves a durable coverage gap. Returning Result<PromptCompletion,...> is
useful but NOT alone sufficient; dropped callers must not lose already received
usage. Broadcast is only UI telemetry. Storage failure retains a bounded pending
receipt and stops further prompts for that session; do not acknowledge success or
silently continue spending. On host restart unmatched begun turns remain unknown.

DefaultOnError prevents typed SDK receipts being exact wire evidence. Add narrow,
bounded observation at the existing worker stdin/stdout compatibility boundary,
correlating outbound session/prompt request id and inbound response before typed
decode. Keep only accounting subtrees/envelope outcome, not prompts/tool content
or arbitrary _meta. Strictly parse original usage fields and record malformed raw
field evidence; typed reserialization must not masquerade as raw receipt. This
transport seam needs a small prototype proving framing/id correlation with SDK
2.2.0 before implementation is committed. An SDK extension is an alternative if
the boundary cannot safely preserve framing; no broad transport rewrite by default.

3. One authoritative run transaction (surge-persistence)
Add runs/accounting.rs and run migrations; writer.rs commands delegate to it.
Unique key (physical_turn,source occurrence); compare immutable receipt bytes plus
versioned domain-separated hash on replay. Exact replay returns original receipt
and adds zero; conflicting replay rejects with ALL transaction state unchanged.
Validate begun turn/binding, insert raw receipt, compute contracted delta, update
baseline and coverage, append UsageAccountedV1/coverage event, and maintain views
in ONE transaction. Add indexes for turn receipt lookup and session contract
baseline; no scan of the historical journal per completion.

Cumulative normalization baseline is scoped to exact provider session lifetime
and contract, with an explicitly proven continuity link across host reopening.
New empty sessions can start at zero only when the contract guarantees it. Loaded
sessions without trusted prior baseline store the first value as an unattributed
baseline, NOT a task charge; later positive deltas are known lower-bound usage.
Missing/invalid fields or declines invalidate affected baseline coverage, never
subtract charges or silently reset to zero. Contract/artifact change begins an
unknown chain; avoid charging historical session work to a new task. Even later
cumulative recovery cannot assert complete turn attribution unless the contract
and exclusive session ownership prove that interval. Per-turn 100/300/50 and
cumulative 100/400/450 produce 450 under their explicit, different contracts.

Store u64 counters as fixed eight-byte unsigned big-endian blobs (strict length)
or one uniformly chosen lossless encoding, not SQLite INTEGER/REAL. Choose blobs
here; all sums are checked Rust arithmetic. Aggregate overflow rejects projection
transaction with a surfaced accounting error; no wrapping/saturation advertised
as exact total. Optional bucket omission never means numeric zero by accident.
Coverage is per bucket/extent with durable gaps, not usage_seq>0. Separate token
coverage, attribution coverage, pricing coverage and projection caught-up cursor.

Registry and run DB are separate databases: there is no honest cross-DB atomic
task projection with the current architecture. Run event transaction is the
authority; work_items sync applies normalized events in bounded pages with a
registry transaction/CAS updating ALL new buckets, coverage and cursor together.
Catch-up is crash-idempotent and eventual. Query reports projection prefix/lag;
read-after-sync can await target prefix. Never describe an incomplete registry
cache as complete accounting. Persistent task totals conserve all attempts;
superseded requirements do not erase historical spend.

Choose migration numbering only after T25's exclusive source work is landed.

Update run_state.rs, run_report/mod.rs, persistence runs/views.rs, work_items.rs,

Expose nullable model, each bucket, extent, gaps and pricing independently.
Cost observations use separate source/sequence/baseline and explicit currency;

Archetype estimates consume only compatible measured extents/coverage; this does
not implement or retire the separate remaining-window quota scheduling requirement.
