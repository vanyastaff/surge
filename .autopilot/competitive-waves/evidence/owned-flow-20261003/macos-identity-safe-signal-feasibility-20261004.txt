2. Direct token API: grounded feasible candidate
Apple libproc wrapper forwards a complete audit_token_t to PROC_INFO_CALL_SIGNAL_
AUDITTOKEN and returns zero or an errno VALUE, not the conventional -1 result [S1].
Kernel proc_info dispatch copies the token. psignal_by_audit_token resolves exact
proc_ident, runs MAC authorization without retained refs, then reacquires that
identity before checking normal caller signal permission and psignal delivery [S2].
proc_find_audit_token checks pidversion; proc_find_ident additionally checks uniqueid
and disallows exec-version change for EXACT policy [S3]. Thus the authorization
wait is not followed by a new unvalidated numeric PID signal. This is an inference
from those explicit checks, not a claim of runtime validation on this host.

Candidate host seam (design only): opaque OriginalMacProcess identity is issued
only from continuous pre-Birth ES lineage and exact original launch ownership.
A leaf-private send_original_signal(original, SIGKILL) uses token API directly;
no public raw-token authority, numeric kill fallback, manual syscall number or
proc_terminate(pid). Symbol/contract unavailable refuses before Release or retains
Unknown after effects. Root held-child ownership and sole wait owner unchanged.
Copied token bytes are bounded DATA; the original coordinator/lineage binds authority.

Exit/exec semantics and errors matter:
- Stale token can fail ESRCH because process exited OR its exec changed pidversion.
  Treat it as an unsuccessful signal attempt, not all-descendant extinction.
  Process current token advances only through continuous observed EXEC target.
  Never repair a stale token by looking up current PID and accepting a new token.
- New EXEC may race a request: retain debt, process its authentic continuity event,
  then issue a separately recorded bounded attempt for that original lineage
  incarnation if cleanup policy allows. Do not spin/retry unchanged ESRCH forever.
- EPERM/invalid token/buffer/API error remains failed/Unknown. Success means signal
  requested for exact target, not termination/reap/domain closure. ES terminal
  lineage+stable live-client drain and frozen authority remain required.
- proc_terminate_with_audittoken chooses sudden-termination behavior, which can send
  SIGTERM instead of SIGKILL [S2]. Prefer explicit signal API for Stop's kill policy.
- Delegated variants require Apple private delegate-signals entitlement [S2];
  not needed for direct host signaling. No assumption that ES entitlement grants
  caller permission to signal changed-credential descendants.

Deployment limitation: header expressly private, symbols unversioned in inspected
public declaration. Review distribution policy and exact minimum/runtime symbol
contract before enabling this profile. This report proposes no private-entitlement
acquisition or OS setup. Normal signal credential/MAC restrictions still apply [S4].
Continuous ES collection still needs its entitlement and appropriate client profile;
direct token safety does not itself require ES enforcement to survive authorization.

3. Mach control task port / task_terminate assessment
A Mach send right refers to a kernel task object, so retaining and identity-checking
the acquired object could avoid numeric-PID retargeting. But acquire-by-PID without
validating that same returned port against original identity is not sufficient.
The published task_for_pid path has POSIX checks, MAC control-task authorization
and possible task-access-server upcalls; ES entitlement alone is not a control-task
port grant [S3]. Same UID/root is not a universal advertised deployment contract.
Name/inspect/read rights must not be treated as control rights.

More decisively, pinned osfmk/kern/task.c:2380–2390 task_terminate returns
KERN_FAILURE when get_bsdtask_info(task) is present [S5]. Installed declaration
alone therefore does not establish termination of ordinary provider BSD processes.
No alternate public BSD task-port termination wrapper has been established by
this bounded review. Do not route to private internal task_terminate_internal,
PID-derived kill, ptrace or target debugger entitlement changes to paper over this.
Mach route remains UNRESOLVED / not selected. A retained port dead-name/error is
not continuous descendant closure, and descendants still need individual capture.

4. ES AUTH_SIGNAL as a guarded numeric-kill candidate
Installed ESMessage.h explicitly says signal events do not support caching and
carry target process identity; self-signals do not produce this event. Use
es_respond_auth_result(..., cache=false) nonetheless. Generic cache-key descriptions
in ESClient.h do not override this event-specific no-cache contract.

Conditional protocol would require a dedicated sole issuing host/broker with
known original audit identity, positive PID-only requests and serialized retained
PendingSignalOccurrence BEFORE calling kill. AUTH handler matches sender identity,
signum and actual target.audit_token to that occurrence; mismatch/unmatched host
signal DENY, never approve by current PID or target pathname. Other processes'
signal requests must follow a separately explicit policy, not global blanket DENY.
An SDK event has no host occurrence nonce: serialize matching host requests, bounded
pending slots and response ownership; no concurrent identical calls or delegated
launchd requests guessed as the current host request. Execute kill outside ES serial
handler so it cannot deadlock waiting for its own AUTH callback. No SQL/async capacity
await in deadline handler; precomputed bounded immutable decision and synchronous
response; record result later with original retained occurrence.

XNU kill holds the selected proc for permission check and psignal [S4]. This supports
an inference that approving its real target cannot redirect that in-flight call to
a substitute PID. It does NOT prove ES delivers every call in every failure mode.
Physical safety cannot be recovered by journaling Unknown AFTER a wrongly allowed
substitute has already received SIGKILL.

Mandatory gaps preventing selection as sole safety barrier:
- Caller/path/instigator muting must not suppress host AUTH_SIGNAL. SDK process
  muting follows submitter/instigator roles, not just target. Inspect actual default
  mute subscriptions; never assume target lineage coverage implies host AUTH coverage.
- macOS27 descendants client scopes callers/descendants. An outside host broker or
  substituted non-descendant target requires explicit actual coverage proof; do not
  assume a callback will fire merely because intended target was a descendant.
- SDK27 says queue-full AUTH normally ALLOWs. es_set_deadline_miss_mode(FAIL_CLOSED)
  changes queue-full and deadline behavior to DENY; verify successful configuration
  before launch, not only handler-level timeout logic. Earlier runtime is unproved.
- Default missed deadline kills CLIENT, not necessarily denies OPERATION. Client
  deletion/death/unsubscription removes enforcement; FAIL_CLOSED declaration does
  not promise persistent enforcement after client loss. Published XNU MAC hook
  and SDK contract do not expose the closed ES implementation proving these cases.
- Process credential/muting/policy changes, missed handler response, no callback,
  client death during pending kill or loss of authenticated occurrence remain
  unresolved physical-gate cases. A pre-call alive check has the same race.
Thus live AUTH_SIGNAL positive/denial tests are useful independent oracles, but
cannot presently justify a fail-safe kill(pid) profile across observer loss.

5. Minimum real acceptance evidence before native selection
No tests run. Required future actual macOS runner checks, not injected receipts:
A. Root/child/grandchild including setsid/reparent actually execute; Stop directly
   token-signals original survivors; ES sees genuine exits, stable drain closes.
B. Token recorded before EXEC rejects old version, then authentic EXEC target token
   allows intended signal; an unrelated still-running sentinel is never affected.
C. Actual stale original token against reused PID fails without affecting substitute;
   use genuine native reuse evidence if obtained. A forged mismatching version is
   supplemental deterministic coverage, not the complete PID-reuse positive oracle.
D. Exit during authorization returns failed/no-effect-on-substitute; independently
   observe sentinel survival and original terminal event. Failure cannot close domain.
E. EPERM (changed target credentials/MAC denial), missing symbol/unsupported runtime,
   gap/client death/overflow all preserve debt and no numeric-kill fallback.
F. For any ES-gate alternative: actual non-cache repeated callbacks, substitution
   DENY, host muting, queue overflow/deadline and client death during in-flight kill;
   independent target/sentinel markers, never merely asserted receipt. Unobserved
   auth still allowing signal falsifies that gate regardless of Unknown projection.
G. Cold host death leaves original observer/owner authority retained; fresh observer
   or fresh token lookup cannot restore pre-Birth continuity. External debt separate.
