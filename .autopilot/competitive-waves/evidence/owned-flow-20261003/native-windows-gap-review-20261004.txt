REQUIRED NATIVE API-PLAN PREREQUISITES

1. Pin broker ownership BEFORE native Birth, not only after daemon startup publication.
Inventory correctly calls for an ORIGINAL Job surviving host death, but that is insufficient if daemon performs CreateProcess then later duplicates ownership to the broker. Crash in that interval can leave a suspended born child, lost root/thread handles and no unique native Birth receipt. Job retention alone does not preserve the actual root terminal observation once its process disappears. Define which executable actually creates Job/process, owns root process/thread/stdio, performs the single waiter, and retains terminal evidence from the earliest successful syscall through durable registry/journal handoff. A broker-owned spawn path is one coherent option; this is a design proposal, not a selected API.
Broker admission must retain exact original operation/run/attempt/opening-control/ordinal, recipe hash and object-incarnation association before allowing Birth. Specify idempotent retries, lost Birth ACK, created-but-unpublished and failed pipe conversion. A reply timeout cannot authorize a second process. Cold reconnect queries the same broker responsibility/object, never CreateJobObject/OpenJobObject by display name as a substitute.
Windows handles are process-relative: a duplicated handle value is meaningful in the receiving process, and DuplicateHandle needs process duplication rights. Define actual recipient confirmation before discarding a sole sender handle; do not serialize a numeric HANDLE and treat it as authority. [DuplicateHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle).

2. Pin authenticated incarnation, original object retention and current Release/Stop authority.
Required DATA includes native backend version/capabilities, machine/boot identity, broker process creation identity, private channel/session incarnation, original domain ID and immutable registration association, root creation identity, held/released/terminal status and monotonic generation/frontier. Job name/PID/session label alone is insufficient. The backend-issued live handle/capability stays private/nonSerde; stored descriptors cannot mint closure.
The API plan must choose an authenticated local broker channel with concrete access checks, bounded messages/slots, replay protection and peer/process identity. Decide whether Job is unnamed and reconnect only through broker, or named with collision handling and validated retention. CreateJobObjectW can return an already-existing same-name object; blindly accepting that result can attach a stale/unrelated Job. Inventory already rejects fresh same-name empty jobs; enforce this at the actual constructor as well. [CreateJobObjectW](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-createjobobjectw).
Choose the dispatcher performing ResumeThread/TerminateJobObject and the exact current generation gate there. An asynchronous Release RPC sent after the caller's last authority check must not become an indefinitely reusable old grant. Pin one-use physical release identity and Stop/release race semantics, including newer controls, lost ACK and broker disconnect. Preserve the admitted syscall linearization limits; do not promise OS/database atomicity. If broker needs persistence authority, its host facade may own that dependency; the surge-process native leaf itself must remain free of SQLite/ACP/MCP imports.

3. Close the actual Win32 ownership/FFI surface, including attribute storage.
Installed0.58 PRIMARY anchors read: Threading CreateProcessW442; ResumeThread1619; UpdateProcThreadAttribute2325; JOB_LIST2713; PROCESS_INFORMATION3838; STARTUPINFOEXW4208. JobObjects CreateJobObjectW22, QueryInformationJobObject70 and accounting572. These wrappers are unsafe, raw HANDLE/PROCESS_INFORMATION/STARTUPINFOEXW are Copy DATA, not owned RAII. Each successful returned process/thread/Job/pipe handle must be adopted exactly once into a reviewed owned type BEFORE any fallible conversion or await; no copied HANDLE owner, assumed StdChild construction or raw-PID adoption. Windows needs a native parcel variant integrating the SAME accepted sole-waiter/retention machinery, rather than a second Tokio child waiter.
Attribute-list sizing first call intentionally fails while returning required size; initialization/deletion states must be explicit. Pin checked attribute count/size multiplication, correctly aligned stable backing allocation, Job and approved handle arrays, initialized STARTUPINFOEXW.cb/flags, and exactly-once DeleteProcThreadAttributeList followed by backing deallocation. Vec<u8> does not by its Rust type guarantee higher alignment. The bindings' LPPROC_THREAD_ATTRIBUTE_LIST implements windows_core::Free by deleting the list; that does not deallocate its backing buffer. Do not combine automatic Free with a second manual Delete or move/reallocate borrowed value arrays prematurely. [InitializeProcThreadAttributeList](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-initializeprocthreadattributelist).
HANDLE_LIST requires inheritable real handles and bInheritHandles=TRUE. Make ONLY intended child stdio eligible, not Job/broker/auth/registry/process/thread handles; prevent unrelated inherited handles under concurrent spawns. Own both pipe ends, clear inheritance on parent ends and retire child ends after creation. No accidental handle inheritance or leak may serve as native retention. [Startup attributes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute).
Member feature closure must explicitly enable Windows Threading/Security/JobObjects plus selected pipe/IO/security/memory APIs; CreateProcessW/CreateJobObjectW are gated by Security. Current ACP Threading feature union is not a valid standalone native-leaf manifest. Aligned HeapAlloc/private namespace/named-pipe choices can add features beyond the inventory's provisional list. Keep workspace version0.58/MSRV1.96 and a small reviewed unsafe capsule; no registry editing or blanket unsafe Send for raw pointers.

4. Pin exact accepted recipe and ResumeThread state machine.
CreateProcessW needs writable UTF16 command-line memory, explicit Unicode environment flags and a correctly terminated environment block; batch scripts need a command interpreter. Exact executable selection, ordered args/quoting, PATH/PATHEXT resolution, environment override/removal/credentials, cwd and console/window flags must match the accepted recipe. Current ACP source already treats Windows command resolution specially; native construction must not quietly replace it with ShellExecute or a different cmd invocation. Use fixed sentinel oracles that avoid publishing credentials. [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw).
ResumeThread is not a BOOL result:1 means expected suspended-to-running transition,0 means already not suspended, greater than1 remains suspended, and0xffffffff is error. Define exact one-shot release outcome and retained debt for every case; no repeated decrements using the same consumed permit. Stop after native success but before Release owns a real child even if target executes zero instructions; it cannot be classified NoChild. [ResumeThread](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-resumethread).

5. Freeze native admission and define membership/terminal disposal without false closure.
Private Job must have no breakaway allowances; actual nested hierarchy, UI restrictions and parent policies affect assignment. Child jobs aggregate membership/accounting and termination scope; test the real CI parent-job environment rather than assuming every job hierarchy is compatible. No create-then-Assign fallback when atomic setup fails. [Nested jobs](https://learn.microsoft.com/en-us/windows/win32/procthread/nested-jobs).
Close all backend assignment/spawn admission before terminal observation; no privileged future assignment may populate the same empty Job after proof. Retain the Job through durable proof. Actual root wait/exit observation and original Job membership must be reconciled by one owner, with current query failures retaining Unknown. TerminateJobObject's success is not a substitute for terminal collection. [TerminateJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject).
ActiveProcesses decreases after terminated-process exit AND reference release; holding every old root/duplicate process handle forever can prevent the selected zero criterion. Capture/retain approved actual terminal evidence BEFORE retiring process/thread references, then query the retained original Job. Account for broker/daemon/test duplicates and survivor references explicitly. Keep a retained-root-handle counterfactual so the fixture does not accidentally hide the ordering issue. [Accounting information](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information).
Wait for actual process termination rather than treating any GetExitCodeProcess value as a standalone terminal proof;259 can itself be an application exit code. Retain typed exit/wait evidence and no stale-ID reopening. [GetExitCodeProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getexitcodeprocess).

6. Fix the containment/escape trust contract without claiming universal remote settlement.
Job membership covers ordinary CreateProcess descendants but explicitly excludes Win32_Process.Create; breakaway and service-created work are separate concerns. General completion messages are not guaranteed, and a Job is not generally a zero-membership wait-signaled object. Notifications may wake query, never independently close. These inventory cautions are sound. [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).
Secured Job means a concrete principal/rights policy, not merely clearing BREAKAWAY flags. CreateJobObject gives ALL_ACCESS; SET_ATTRIBUTES/WRITE_DAC can alter policy and ASSIGN_PROCESS can reopen membership. Pin broker/daemon rights, target inherited rights and named-object DACL/access behavior. If accepted targets share the same unrestricted identity, do not imply DACL grants to that identity distinguish trusted host from target; state the selected trusted-executable boundary or enforce a separately reviewed manager-controlled profile without changing accepted credentials silently. [Job security/access](https://learn.microsoft.com/en-us/windows/win32/procthread/job-object-security-and-access-rights).
For mediated external adapters define occurrence/terminal evidence; for unmediated WMI/service/remote launches retain the declared external Unknown rather than certify arbitrary providers from Job-empty. This is scoped to tracked declared responsibilities, not a demand for impossible universal remote no-effects guarantees. Linux migration isolation and macOS continuous observer/signaling/deployment remain distinct required dependencies.
