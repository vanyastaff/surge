BLOCKER1 — Section2's cleanup ID backing is too small for its accepted ID contract.
Routing string IDs are allowed up to4096 UTF8 bytes. Cleanup backs only an8KiB raw frame and16KiB delivery representation per cleanup occurrence and explicitly claims this allows a4096-byte ID plus fixed denial/cancel envelope. JSON escaping breaks that calculation: an accepted ID comprising4096 U+0000 characters is4096 decoded UTF8 bytes, but its serialized JSON string occupies24576 bytes plus quotes. Such an incoming normal request fits the8MiB frame, depth/node/ID limits, yet any exact denial/error/cancel echoing that ID exceeds the supposedly guaranteed cleanup8KiB raw permit. Escaped IDs with quotes/backslashes also exceed the simplistic fixed-envelope arithmetic. Silently slicing/normalizing the ID would corrupt correlation; the plan correctly forbids this. Refusing the reply above8KiB is conservative, but contradicts its explicit backed cleanup/progress guarantee, rather than solving it.
Choose and document an exact admitted-ID encoding bound (an additional compatibility delta, independently tested), or increase cleanup raw/delivery partitions to back the real worst-case serialized envelope and simultaneous typed/serialized representations. Recalculate all per-connection/global/run cleanup pools and counts together. Include delimiter, requestId property/error fixed message, and the delivery copy graph; increasing raw alone does not prove the16KiB delivery peak. Keep ordinary traffic unable to consume backed cleanup capacity.
Required independent oracle: actual callback/request with a literal fixed long escaped/control-character string ID, normal capacity saturated, then cleanup denial/cancel. Verify exact emitted ID/byte count, or intentional BEFORE-admission rejection under a documented encoded-ID rule. Pair plain ASCII and multibyte/non-ASCII cases. A4096-letter ASCII-only test cannot expose this defect.

BLOCKER2 — Sections2 and7 need an explicit ordered legacy compatibility exception before unknown routing refusal.
Section2 says unknown input without an exact admitted lane records Attention and closes reads/transport. Section7 simultaneously promises the exact object notification-ignore policy. Current rmcp1.6 async_rw.rs222–267 is more specific than 'unknown no-ID object': on typed-decode failure, valid JSON with a string method is ignored if (id absent AND method not standard), OR (method starts notifications/ AND is not a standard notification). The second branch applies even when an id is present. Known standard methods with malformed notification shape are not all ignored. Arrays must remain rejected under this revised owned contract.
Pin the classification order: bounded capture/preflight and routing-key validation; attempted typed classification; exact upstream compatibility-ignore predicate where applicable; THEN generic malformed/unmatched response/unregistered request/unknown-envelope refusal. A compatibility-ignored object must recycle its bounded ingress storage without manufacturing a result, cleanup reply, terminal receipt or Attention merely because it lacks an admitted delivery lane. It must not log method/body. Conversely a genuinely unmatched response ID or unsupported incoming request must not be relabeled ignored to evade debt. State whether an intentionally tighter rule for id-bearing unknown notifications is desired; if so document it as a compatibility change instead of claiming exact preservation.
Required actual counterfactuals: custom non-MCP no-ID notification followed by a valid pending response; unknown notifications/custom with and without id; standard method malformed shape; real unmatched response ID; whole arrays/empty arrays. Keep ignored-object progress distinct from unknown-before-valid-response close/Attention. The latter closes the stream by policy; it is not evidence that the later response was delivered.

ADVISORIES / IMPLEMENTATION ACCEPTANCE CONSTRAINTS
A1. The128MiB MCP/32MiB ACP delivery bound is plausible as a conservative peak under8MiB/1MiB raw caps and new depth64/node32768/4096 caps, but is still a promised authored proof, not established memory accounting. Pin byte/node/depth/string counters and checked capacity arithmetic in the adapter; audit actual to_value/from_value/clone/serialization paths and overlapping raw/AST/typed/SDK representations. In ACP RawJsonRpcMessage serialization currently clones a variant; raw deserialization first constructs Value then from_value; outgoing to_untyped_message queues owned data. Response-hook paths can clone Value, though some hooks are feature-gated and not used by this workspace. Charge only actual authored feature paths but do not assume four representations without enumerating them. postdecode refusal cannot retroactively prevent an over-budget transient allocation. Preflight plus a demonstrated upper bound must precede allocating each representation.
A2. Generated host handler data must have an actual bounded producer/serialization seam, not merely a post-return size check. If a supported handler can construct an unbounded Value before capture, calling it an unsupported owner after the allocation does not establish the byte guarantee. List supported owned producers and where their bound is enforced. Public LeasedResult APIs/caches/caller consumers must not expose uncharged clones or return bare T while dropping its lease; audit the actual whole downstream lifetime, including bootstrap Peer info and full catalog caches.
A3. Clarify leases for valid notifications versus callbacks and ignored objects. One callback lane per connection is a tactical compatibility/concurrency constraint; multiple simultaneous admitted callbacks must either have independently backed lanes or be refused/closed without losing existing receipt/charge. The examples must not imply32 productive lanes when only two maximum-result lanes are backed.
A4. Gate fairness needs an implementation-level total budget, not just10ms acquire plus10ms busy_timeout per SQLite statement. Use bounded indexed current-control queries, a fixed statement count/deadline and no filesystem/graph hydration on IO dispatch. Service ready read/control peers between gated writes, and test contention with another connection's result/Stop. Temporary gate failure keeps debt and emits no wire grant. Admission linearization is explicitly not OS/cross-WAL atomicity; do not upgrade it to 'no byte after Stop commits'.
A5. Safe original FD lifetime, partial cursor/write behavior, EOF/CRLF, no-newline bounded capture, checked ID allocators, and local non-Send ACP handles must be exercised independently. Keep no await between ACP enqueue and retained handle/id bind; failed bind stays EnqueuedUncorrelated/Unknown with closed transport latch. Automatic-drop cancel never bypasses cleanup registration/current frame gate.
A6. SameArc retention, lost/duplicate Taken, durable protocol(b), diskfull and unconfirmed shutdown preserve original claim/control history. Payload/raw release and native/external settlement are distinct responsibilities. No factory or custom sink can mint physical closure from a neutral observation/token, timeout, SDK destruction or EOF.
A7. Resource policy values and new encoded-ID/depth/node caps are documented owned compatibility deltas. Global8GiB delivery means at most about21 maximum MCP bundles even though connection count cap is64; that is a ceiling interaction, not an arithmetic contradiction. Avoid advertising64 simultaneous maximum MCP connections. Reserve credits do not guarantee OS memory availability; fatal panic containment still cannot claim cleanup/durability after OOM/process death.
A8. Final vendor tree hash/feature/license/MSRV closure remains a postwrite freeze deliverable; no impossible prewrite hash requirement. No source closure or actual implementation check is claimed by this report.
