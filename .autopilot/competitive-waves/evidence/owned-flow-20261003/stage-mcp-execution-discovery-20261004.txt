Candidate architecture for independent review:
1. One stage-owned immutable dispatch catalog built from the accepted resolved
   tools, exact server identity and frozen private manifest. Exposed names must
   have deterministic conflict handling for duplicate servers/builtin collisions;
   plain name lookup must never select another server by accident. Explicit
   wrapper schema separates engine call_id from untouched server arguments,
   avoiding collision with a server's own call_id field/schema. Exact provider
   compatibility and tool naming rules need primary SDK/source verification.
2. Preserve authenticated StageEndpoint context and stage generation checks.
   Native authenticated StageToolCall, never ToolObserved, enters execution.
   Revalidate visibility/sandbox/whitelist against frozen catalog at invocation,
   not merely during tools/list. Reuse canonical dispatcher for loop guard,
   timeout/output spill and typed escalation instead of a second executor.
3. Durable invocation identity includes original item/revision/attempt/run/
   workspace + invocation/stage generation + server occurrence/tool + canonical
   exact argument digest + stable caller operation ID. Validated identity and
   original launch Arc remain host-owned; model inputs cannot mint authority.
   Generic journal append cannot forge an executable intent or settlement proof.
4. Register durable effect obligation BEFORE any possible physical call; only
   then journal projection. Respect registry/run DB separation, monotonic causal
   receipts, crash windows and reconciliation. After ALL queues/awaits use the
   shared synchronous final host fence immediately before actual SDK enqueue.
   Known no-dispatch can settle through owner evidence; uncertain dispatch is
   not retried automatically. Need exact reviewed completion semantics: a tool
   response proves RPC outcome, not completion of arbitrary asynchronous remote
   work. Remote continuation stays an external obligation without true proof.
5. Persist exact successful MCP content/structured/meta without lossy conversion
   through debug text. Error diagnostics remain opaque per accepted boundary.
   Durable result BEFORE provider reply supports exact replay; changed-body same
   ID rejects without effects. Cancellation/timeout/lost reply after dispatch
   remains uncertain until actual settlement, never false clean shutdown. A
   returned result cannot retire an unrelated external obligation or grant
   suspension by caller boolean.
6. Cold receipt hydration must bind original journal occurrence, closed dispatch
   epoch and accepted revision; reject malformed/foreign/stale/duplicate records.
   Retried same ID replays only a proven stored result, otherwise reports the
   unresolved state without repeating side effects. New stage generation must
   not accidentally reuse/relabel an old uncertain invocation.
