Residual effect-plan findings

OF-EFFECT-01 — health-monitor RPC bypass is not explicitly mapped.
Actual connection.rs::spawn_health_monitor (~589) calls rs.list_tools(None) directly, not McpServerConnection::list_tools or call_tool. Therefore inserting before_effect only after ensure_connected in those two methods leaves the periodic background probe unfenced. The monitor also invokes ensure_connected for proactive restart; spawn checks must cover that path too. tools/list is a physical advancing RPC, not read-only local status or cleanup. A retained observer/claim must gate the direct probe immediately before forwarding, and a refusal must not authorize re-open/reconnect work. Explicitly map this branch in the plan and add a deterministic stopped/archived-owner health tick oracle. Shutdown, cancellation and child reaping remain exempt; health probes are not cleanup.

OF-EFFECT-02 — facade validation is not the final physical provider boundary; define Stop linearization or carry the host fence further.
Actual AcpBridge::open_session (acp_bridge.rs:132-158) first awaits open_slots, then sends BridgeCommand::OpenSession to a separate worker and waits for reply. send_message (:162-179) also queues a BridgeCommand for later worker execution. RecipeAdmissionBridge::open_session additionally performs registry admission work before raw delegation. A new decorator validating only before inner.open_session/send_message cannot prevent a control change occurring after that validation but before physical spawn/prompt. Retaining a genuine claim prevents a second owner stealing the OS lease; it does not by itself prohibit Stop/archive from changing current control during those awaits.
The revised plan's physical barrier oracle needs a precise admission contract. Choose either: (a) a durable/linearized effect admission ordered against Stop/archive, with explicitly defined already-admitted outstanding operations and retained cancellation/cleanup, or (b) a host-only validator/fence carried to the worker's final physical write plus defined serialization/admission semantics. No public caller bool, no untrusted callback authority and no dropped claim are permitted. A decorator-only check does not establish strict zero physical write after a Stop which wins the final effect boundary. This need not be a broad ACP trait rewrite, but the plan must identify the actual authority seam and test a delayed open-slot/queued-worker/prompt barrier, not only a barrier before the decorator check.

OF-EFFECT-03 — pre-spawn control check precedes awaited writer-intent publication.
Actual connection.rs::spawn_and_serve awaits observer.before_child before building/spawning the child. Existing McpWriterObserver::before_child awaits durable writer_coverage::begin event recording. Checking current ownership/control before delegating that observer is an earlier check; Stop/archive can win during the await. The companion plan must place the chosen final effect admission after writer intent completes and before actual child spawn, with the same retained claim and no path that treats the intent record itself as permission. child_started revalidation before handshake prevents initialization after refusal but cannot undo a spawn that already happened. Add a real barrier after writer intent/before spawn, change control, and require zero child spawn when Stop wins; cleanup any already admitted child under the separately defined admission ordering. This is the MCP counterpart of OF-EFFECT-02, not a request to remove pre-dispatch writer evidence.

Otherwise the effect direction is coherent: private wrapper and observer are selected from authenticated same-run inputs plus retained real claim; Legacy default methods grant no owned-flow hydration; tool/permission replies are checked; state/subscription remain observational; cleanup always delegates. Initial Pending/Reserved permission is separate from Started continuation. Started requires actual unique authenticated startup verification and ACK, latest binding/current control, and ContinueReserved requires confirmed cleanup. Suspended/Attention/Terminal/canceled/missing intent cannot advance effects. Store validation must observe these as a coherent current predicate at the chosen admission boundary; cached stage validation is insufficient. All owned run-task initial/cold paths and monitoring tasks retain the same claim Arc through admitted effects and cleanup.

The current drafted validate_owned_flow_effect code is context, not accepted implementation. This review does not sign off its SQL observation ordering or substitute token validation for the actual startup journal oracle. A claim/pin alone grants neither initial provider permission nor a continuation.
