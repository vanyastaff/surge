1. Non-negotiable meaning of authority

A completed direct std Child is leader settlement. It is not descendant-domain
closure, not remote-effect settlement, not suspension authority, and not proof
that a caller-canceled awaiter never physically dispatched.

A durable writer obligation exists BEFORE each potential physical writer/effect.
An unresolved obligation always blocks a clean suspension acknowledgment and a
new dispatch epoch in the same retained attempt/workspace. A host OS lock may
vanish on crash; the obligation must remain authoritative without that lock.
The same original WorkItemLaunchClaim Arc is retained by the actual lower-level
owner, not replaced with a serialized receipt or a freshly issued claim token.

Clean Continue/wake requires a complete immutable original closure set for the
prior epoch AND exact original startup/accepted input/journal association. Every
real provider, MCP child, shell/hook child and host/external operation belongs
in that set. Success/EOF/SessionClosed and cleanup_confirmed flags are projections,
not capability constructors. A valid native local-domain closure does not close
an unresolved external service operation.

short registry transaction, bracketed by actual lock verification. No DB connection
survives async waits or native join. claim token is current ownership validation;
immutable closure identity binds stable launch object and ORIGINAL epoch, so
cold claim-token reissuance does not rewrite or invalidate genuine old proof.

plus persistence-issued reservation are both needed, neither alone is sufficient.

No new private HMAC namespace/key is required for Empty: private-input auth remains
separate and unchanged. No inherited credential capture, raw command/env or panic
payload enters the closure ledger/journal/diagnostics.

5. Registration/spawn protocol and every cross-DB failure window

Registry DB and per-run events.sqlite are separate WAL databases. Do NOT claim
an atomic cross-DB transaction, ATTACH-WAL atomicity or synchronous SQL read making
journal mutation atomic. Use monotonic authority-first protocol:

A. Under original claim, registry reserve_writer commits ReservedUnestablished,
   epoch/writer_generation increment and irreversible occurrence/nonce BEFORE
   journal intent enqueue and BEFORE any physical spawn.
B. A typed RunWriter::commit_writer_intent(reservation-issued permit) commits the
   actual origin event and returns private IntentJournalReceipt with run/epoch/
   occurrence/seq/raw-byte digest. Registry binds that receipt write-once.
C. Native PreparedDomain is actually created/child held as required by backend.
   Registry binds original domain identity. Typed journal establishment commits;
   registry binds its receipt. The actual target cannot execute between create
   and the final gate. Failures retain owner; no replacement domain on same ID.
D. Final synchronous registry admit_writer_effect checks receipt association,
   current Running epoch, complete startup and prior closure authority, stable
   lock, accepted binding/workspace and latest permitting control. It performs a
   short WRITE admission recording the particular physical occurrence before
   spawn/resume/first wire enqueue, with no caller await in between.
E. Actual owner performs that one admitted effect immediately; later Stop may
   close admission but must settle already admitted owners/operations. A Stop
   committed BEFORE D causes zero physical effects. Admission receipt is not an
   exit/completion proof. SDK/OS-internal I/O may finish an already admitted effect;
   any later Surge-owned await requires another last gate after it.

Crash/cancel between A and B leaves an orphan registry obligation. Missing journal
intent/PID NEVER means no child. It remains Unknown/Attention and is inspectable.
A genuine pre-spawn cancellation can close only while the actual retained launch
factory/reservation proves its unconsumed physical permit and no created child;
this is a private NoChildProof issued by the same native owner, not Drop/channel
closure/lost waiter/absence of a PID. If that owner is lost, no NoChild is guessed.
For a genuine NoChild proof issued after A but before B, typed journal projection
records CanceledBeforeDispatch with the ORIGINAL registry reservation receipt and
its immutable writer_generation. The complete closure set includes that obligation
even though no physical WriterEstablished event exists. This is positive issued
no-child evidence, never inference from absent intent/PID. A queued intent from a
pre-Quiescing reservation can only project its already existing origin/cancel/
closure; it cannot gain execution permission behind freeze. New generation or
unregistered late intent is refused/conflicting. Registry-only unresolved orphans
still block the set even if the whole journal contains no writer event.

Crash after journal commit before registry bind retains an unbound obligation;
reconcile the exact original committed receipt and binding, without spawning.
Crash after native create before establishment commit is unresolved even if child
was suspended. Native owner retains it; host-death recovery proves real native
identity if capability permits, otherwise stays Attention.

Generic AppendEvent/AppendBatch reject new authority-bearing writer/domain/closure/
seal/continue variants AND owned writer intent/establishment claims. Typed commands
only accept live host permits bound to actual registry reservations. Legacy old
events remain readable but cannot mint new authority. All writer-producing APIs
must follow A–E; a late unknown legacy intent in an owned run is a conflict.

Run writer's own epoch marker/generation is installed through typed birth command.
Every typed writer append uses the bound permit and serialized writer command
queue. freeze command closes writer-generation acceptance after registry Quiescing;
late queued writer intents either settle their PREEXISTING registry obligation
or are refused, never escape the registry closure set. Every lower-level owner
has that same bound writer reservation, so unregistered physical effects cannot
occur through the owned production host boundary.

6. Actual local closure and external obligations

Native owner returns NativeDomainClosure only after all local domain obligations
are physically proven closed and root reaped. It retains original observer/claim
until the host persistence acknowledgment or durable uncertainty boundary.
Registry commit validates exact original domain/nonce and writes actual local
closure. Typed journal projection follows; if it fails/crashes, registry closure
is still durable, but suspension remains blocked until exact projection repaired.
This is not LostReceipt -> new child or a replacement launch lease.

Host operations that can outlive their local process need separate effect IDs
BEFORE dispatch. Local-RPC completion/pipe EOF/HTTP200 is not remote quiescence.
Adapters may close an external effect only with their reviewed provider-specific
terminal/cancel/settlement evidence bound to the actual request occurrence.
Unsupported/uninterpretable completion remains ExternalUnknown. Retain exact
pending owner/receipt across canceled waiters. Finite synchronous host filesystem
operations settle after their real blocking worker completes; future cancellation
cannot certify completion. Arbitrary shell/MCP is not declared local-only merely
because the fixture is benign.

Existing MCP and shell/hook begin(...local_effects:false) cannot be flipped to true
as a shortcut. Introduce explicit LocalWriter and ExternalEffect obligations at
the real effect boundary, preserving unknown external obligations from existing
history. Model ambiguity in legacy records as unresolved. Closing transport may
close its local domain; it does not erase external obligations. A valid positive
twin requires a supported reviewed settlement contract for its actual effects,
not a config checkbox saying trust_this_server. This adapter contract still needs
concrete design and independent review before claiming unrestricted MCP recovery.

7. Freeze/suspension journal/registry protocol (no fictitious atomicity)

1 Run task stops graph dispatch; registry freeze_execution_epoch atomically changes
  Running -> Quiescing, closes new reservations/admissions, records exact requested
  control generation and current writer_generation. All subsequent final physical
  checks refuse. Pending already reserved obligations remain in the set.
2 Request cancellation/close of provider, MCP, shell/hook and external owners.
  Always permit denial/cancel/close/wait/reap bookkeeping while dispatch closed.
  Do not impose success timeout on actual owners. Timeouts become Attention.
3 Each actual owner commits exact closure/NoChild/effect settlement and journal
  projection. All existing reservations, including orphan/unbound ones, must be
  resolved. Independent actual OS survivor/escape observation is mandatory.
4 Typed journal barrier computes FULL contiguous history in one held read/write
  transaction, not only startup prefix. Pure reducer checks every origin/domain/
  closure/scope/epoch, duplicates/conflicts/unknown events/late writers and builds
  exact closed writer+effect set. Match registry ledger snapshot and generation.
  Registry freezes immutable closure set only when every obligation is complete.
5 RunWriter::seal_owned_suspension(HostSuspensionPermit, frozen_cursor_snapshot)
  serializes behind actual prior owner events. In ONE JOURNAL transaction it checks
  current head, exact closure projection set, no unregistered/late writer, snapshot
  pending phase and attempt/startup binding; computes final raw-byte prefix digest;
  writes ExecutionEpochSealed and RunSuspended plus snapshot. Snapshot at_seq is
  the final actual prefix BEFORE those seal events, after all closure observations;
  do not retain the pre-cleanup snapshot_seq used by current prepare_suspension.
  No caller may supply cleanup_confirmed as proof. Return private journal receipt.
6 Registry acknowledge_suspension validates that receipt by actual journal inspection
  under exclusive owner + unchanged closed epoch/generation/set identity, then ONE
  registry IMMEDIATE transaction updates control Suspended, attempt Suspended,
  closure ack receipt and capacity association. Only then UI reports suspension
  and original actual owners may finish releasing launch responsibility.

Crash after step4 before5 is ClosedAwaitingJournal, no clean ACK/effects. Crash
between5 and6 can replay exact original journal receipt after full inspection;
it does not resuspend/restart/recreate native writers. Crash before any proof is
Unknown. Journal/registry discrepancy, late writer or newer control fences step6
and persists Attention; it never chooses whichever DB looks greener.
The journal seal cannot be bypassed by a read-only SQL snapshot. Correctness comes
from registry epoch closure BEFORE any waits plus exclusive original lease and
restricted RunWriter ownership protocol; every gap retains a blocking obligation.

8. Attention BEFORE unresolved owner release, including disk/runtime failure

mark_execution_attention is ONE registry IMMEDIATE transaction: validates original
claim/epoch and expected current generation/revision, sets epoch Attention and
closed-admission, attempt Attention, latest relevant control Attention without a
clean fence, preserves active_run/workspace and ALL unresolved obligations, invalidates
wake permits and records bounded reason code. It commits BEFORE intentionally
dropping the last unresolved launch-owner Arc. No settle(terminal) clears active_run
while any obligation is unresolved. Task completion/workspace archive/delete/new
attempt must consult the same obligation ledger and cannot bypass it.

Live actual native children/domains/operations still retain original Arc through
the independent actual owner until physically settled; Attention is not permission
to discard child/domain ownership or signal a stale numeric PID. If only incomplete
observation remains after actual owner exit, durable Attention allows releasing
that owner's Arc while retaining the blocked obligation forever until real proof
or an explicit future reviewed resolution exists. Reclaiming the now-free OS lock
confers reconciliation-only authority, not dispatch permission.

If Attention persistence fails, DO NOT release intentionally. Retain original
owner and retry with bounded safe diagnostics/backoff; shutdown barrier stays
unconfirmed. An unavoidable process crash releases OS locks, but BEFORE any effect
A had durably inserted its unresolved obligation; a new host therefore blocks
without requiring the missing Attention projection. Storage unreadable is also
refusal. No kill/abort path pretends it committed Attention or cleanup.

Move daemon supervise_completion's unconditional drop(claim) behind verified
closure acknowledgment or committed Attention. Runtime-cancelled supervisors cannot
be sole owners: native/process owner and authority settlement coordinator hold
original Arc independently, registered before first postspawn await. Admission/
broadcast completion releases UI slots, not unresolved workspace/process authority.
