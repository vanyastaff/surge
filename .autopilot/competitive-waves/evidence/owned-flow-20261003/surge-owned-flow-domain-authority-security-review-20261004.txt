What is solid and worth preserving

The central authority-first model correctly stops a journal-less orphan from being treated as
empty. Registry reservations precede potential effects, separate WAL databases have no fictitious
atomicity, native proof and registry reservation are both required, copied public IDs cannot settle
another native domain, and typed generic-append exclusions prevent JSON/event authority forgery.
Dispatch closes before cleanup; unresolved obligations survive crash and block follow-up attempts
in the retained workspace. Historical closure sets remain immutable; current claim-token validation
is separate from original epoch/native proof identity. Attention before intentional unresolved-owner
release and no terminal settle clearing active_run are necessary corrections. Complete whole-journal
folding, raw-byte prefix receipts and exact startup/private-input association are appropriate.

The plan correctly refuses to elevate leader exit, empty process group, SessionClosed, EOF,
HTTP200 or canceled waiter into complete local or external closure. It honestly retains broad
macOS setup and external contracts as unresolved; this honesty is why integrated authorization
cannot yet be ACCEPTABLE. Conservative refusal alone cannot complete populated cold recovery.

R1. Split native creation admission from target release admission (concrete algorithm contradiction).
Sections 2/5C require an actual held/suspended child and original identity before establishment;
5D then claims its first final gate occurs immediately before spawn/resume and that Stop before D
causes ZERO physical effects. On Windows/macOS a child already exists in C. On Linux clone3 creates
a process too. Suspended child creation is still a physical operation needing prior durable debt,
retained ownership and a last current-control gate; it cannot be hidden in preparation.

Specify PreparedDomainWithoutChild and HeldNativeChild distinctly. Reserve/bind a domain's original
kernel identity before execution where the primitive permits; then admit CREATE synchronously just
before the native creation syscall. Transfer/retain the actual created handles/root identity
immediately, bind establishment, then admit RELEASE/RESUME separately after every intervening
storage/readiness wait. If Stop precedes CREATE: zero child. If Stop follows CREATE but precedes
RELEASE: real held child must be settled, never NoChild; zero target execution. Failure/crash after
CREATE is an unresolved original debt even where target code never ran. On a backend that can
atomically create directly executing target in a prebound domain, explicitly identify that single
boundary and the postcreate identity capture obligation; do not claim root identity was known
before creation. Rework NoChild proof to include an unconsumed CREATE occurrence, not merely an
unconsumed RESUME permit. Register the retained factory/settlement owner before the first registry
reservation and any post-reservation cancellation boundary, so A-before-B has a genuine issuer.
