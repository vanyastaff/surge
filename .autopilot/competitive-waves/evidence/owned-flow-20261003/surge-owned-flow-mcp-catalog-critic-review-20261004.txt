DESIGN AGREEMENTS / NONBLOCKING IMPLEMENTATION GUARDS

1. Additive selected-list API and private immutable MonitorPolicy are narrow reuse.
   list_tools_for_servers must perform complete configured-name validation and
   sort/dedup BEFORE its first awaited query. In either monitor mode it must not
   call ensure_monitors_started. Empty selection starts no tasks/child/RPC. Unknown
   selection containing valid names must fail without partially querying them;
   validate-all tests need valid name sorted BEFORE the unknown one. Preserve the
   existing ServerNotConfigured type and opaque transport errors, not raw causes.

2. OnDemand must be checked in the single ensure_monitors_started seam before
   any atomic mutation/task creation. It applies even when list_all_tools or
   call_tool reaches that helper: no background monitor can be enabled later.
   Existing from_config/from_config_owned keep LegacyProactive. Only legacy
   list_all_tools/call_tool start monitors; selected-list never does so itself.
   Do not reuse an already monitored global connection Arc for a run. The actual
   resolver currently copies refs into new connections; retain that behavior.

3. Keep mcp_spawn_policy(server_override.unwrap_or(node_mode)) exactly. Existing
   unit tests explicitly allow WorkspaceWrite override under a ReadOnly node and
   deny ReadOnly override under FullAccess. This change is earlier application of
   existing policy, not stricter privilege intersection. Build the configured
   intersection before forwarding names so absent optional mcp_add names remain
   legitimate when MCP is disabled. Library explicit unknown names remain errors.
   Keep None versus Some([]) whitelist and deterministic tool/collision ordering.

4. Cross-stage denial means no new catalog/routes/background work from the later
   stage. It does not terminate the original child, revoke an already admitted
   earlier operation, reset connection/restart state, or establish domain closure.
   Preserve original registry/connection/observer/claim ownership; no per-stage
   reconstruction/drop to make a no-probe assertion pass. Sequential stage tests
   should observe the existing child's lifetime/identity and then independently
   verify no probe/reconnect after death/timer ticks. Concurrent earlier admitted
   operations retain their existing responsibility; do not invent global latest-
   stage revocation semantics in this bounded fix.

5. Removing monitors intentionally removes proactive reconnect for engine runs.
   Keep existing synchronous ensure_connected/list/call behavior and restart
   budgets. A dead service may produce the existing transport failure before a
   later explicitly selected operation reconnects; do not add retries that hide
   it or reset attempts. Test real selected reconnect failure/backoff/exhaustion,
   then allowed success, and prove unselected servers remain untouched throughout.
   Preserve single deadline across catalog pages and effective call timeout.

6. Existing final HostWriterObserver checks must remain at physical spawn/init,
   each page, and tool-send after waits. Selection is not durable run admission.
   Keep caller cancellation ownership, neverpolled close, retained send, std child
   transfer/Taken and terminal barrier invariants unchanged. Shutdown remains
   cleanup-capable. No new Closed emitter, fake cleanup flag, NoChild inference or
   native backend is authorized. A selected catalog canceled mid-initialize must
   still retain/settle the original actual child through the existing owner.
