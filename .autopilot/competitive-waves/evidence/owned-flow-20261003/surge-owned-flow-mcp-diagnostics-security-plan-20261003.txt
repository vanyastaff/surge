Bounded blocking findings

MCP-DIAG-01 — framing/representation is unspecified and can leak accepted literals.
connection.rs:774-789 converts stderr into AsyncBufReadExt::lines, then applies redact_line independently. A declared argument/env value containing LF or CRLF is split and separators stripped before comparison with its full literal. Every component can persist in the tee and tracing. A literal set applied after heuristic redact_line can also lose part of a known literal when that heuristic masks a substring first. JSON/Debug escaping changes newline, quote, backslash and Unicode representations, so comparing only raw literals against formatted errors is insufficient. Arbitrary short literals and overlaps cannot be filtered out by a minimum length or naive sequential replace (masking one substring may leave the remainder of an overlapping longer secret). An unbounded next_line can allocate an arbitrary child line; MAX_STDERR_LINES bounds count, not bytes. Cutting oversized input first can disclose an unmatched prefix.
Required shape: explicitly define whether diagnostics are opaque for frozen transports or bounded exact-literal sanitization with a genuine raw-byte/framing boundary. Opaque diagnostic payloads are the simpler robust option for this unit. If retaining text, define bounded buffering across writes/line delimiters, longest/union matching on original input, one-pass mask insertion, known formatting escape handling, and fail-closed oversize/invalid-UTF8 policy without flushing any unmatched secret fragment. Empty literals carry no bytes and can be ignored; every nonempty literal, including one Unicode scalar or one byte, requires coverage. Reject malformed transport inputs with safe reason codes before spawn when rejection is part of the declared bounded input contract; never truncate or mutate the actual accepted spawn to make redaction easy. An inability to sanitize must suppress the diagnostic or refuse safely, never return the raw string. Literal matching cannot be claimed as universal protection against a malicious child's arbitrary encodings/character transformations; state that limit or make untrusted diagnostics opaque.

MCP-DIAG-02 — public error/cleanup paths extend beyond stderr and StartFailed.
connection.rs spawn_and_serve creates StartFailed.reason from observer/spawn/handshake error.to_string at 343-347, 375-378, 394-397 and 418-422; handle_service_error at 494-503 stores raw e.to_string in Transport/Service. shutdown at 645-654 logs raw %e then stores e.to_string in CleanupError::ServiceJoin. RegistryCleanupError formats failures with Debug; WorkerJoin also retains a diagnostic. Derived McpError Debug/Display exposes its stored String fields. Sanitizing only a later Display implementation leaves Debug, reason field inspection and chained wrappers unsafe.
registry.rs::call_tool additionally forwards error-flagged CallToolResult content without sanitization. routing.rs:378-384 turns that content into ToolResultPayload::Error; stage/agent.rs:1997-2012 journals its plain ContentHash and then sends the error message to ACP. Correction: this journal contains a hash, not the raw body, but known private transport bytes must not survive into the diagnostic input or its public unkeyed digest. stage/agent.rs:760-764 also traces list_all_tools errors. The safe boundary must precede these returned/hashed/formatted values.
Required shape: construct safe-only diagnostic fields at the connection/registry origin, after structured error classification and before formatting/logging/return/hash. Do not retain raw underlying errors in public source chains. Error-flagged tool response diagnostic content must be safe before registry returns it; define preservation of is_error and functional non-error tool results separately. Safe bounded server IDs/reason codes may replace private text; all textual fields emitted alongside a diagnostic need consistent handling. Connection Debug currently hides transport but configuration() returns a full McpServerRef whose derived Debug exposes it; it remains runtime-private and must never be Debug-logged or projected into public diagnostics. Redactor/set Debug must itself omit values. Redaction applies to diagnostics, not actual ordered args/env/command, whitelist, timeout, sandbox or private authenticated envelope bytes.

MCP-DIAG-03 — pinned rmcp emits peer payload diagnostics before Surge can sanitize errors.
Confirmed exact installed rmcp 1.6.0 source: service.rs:759 logs ?peer_info at INFO during client initialization; :985 logs ?notification at INFO; :990 logs cancellation reason. service/client.rs:108 logs unexpected ?notification and :137 unexpected ?message at WARN during handshake. transport/async_rw.rs:265 logs the entire malformed UTF-8 line_str at DEBUG, and :228 logs a peer-supplied notification method at TRACE. A controlled accepted MCP child can echo its received args/env in initialize serverInfo/instructions or a notification and produce public logs before any connection McpError sanitizer runs. The normal INFO handshake leak does not require debug logging.
Required shape: an enforced diagnostic suppression/sanitization boundary for rmcp-origin records covering handshake, codec and all background/reconnect/cleanup tasks, before any subscriber/file can observe fields. A subscriber/dispatch scope is viable only with actual proof it covers spawned rmcp tasks; a temporary thread-local guard across an async call is not sufficient. A mandatory target suppression policy with safe Surge-owned replacement metadata is another bounded option if it cannot be re-enabled by env/operator filter. Do not patch the registry transport values or claim outer redaction intercepts dependency tracing. Audit the pinned API/source boundary again after choosing the architecture; no broad unrelated dependency sweep is requested.

Sibling primitive limitations
ACP shared/secrets.rs::SecretsRedactor uses heuristic redaction then repeated literal.replace and hides Debug. It is not a streaming or formatting-proof primitive suitable for direct adoption. Its worker explicitly says chunk-local best effort is not an information-flow boundary and excludes universal encoded/split-secret claims. That limitation must not be silently promoted into a stronger T25 diagnostic guarantee.

Recommended bounded revised plan
Use automatic per-connection runtime protection derived from the authenticated effective frozen transport. Keep exact spawn values immutable. For this unit, opaque/safe-coded child stderr and externally originated transport/service/cleanup/error-response diagnostics, together with an enforced rmcp logging boundary, avoids having to certify arbitrary streaming literal masking. Literal redaction can remain an extra compatibility/debug aid with explicit limitations; it cannot be the sole secrecy proof. If diagnostic text preservation is required, the plan needs the exact bounded framing/representation algorithm and exhaustive surface coverage above before code.

Observable acceptance additions
Actual child receives exact command path, ordered distinguishable args and env (including empty, whitespace, quotes, backslashes, short, overlapping, Unicode and multiline cases); recorder evidence containing raw sentinels must remain private/test-owned, never copied into public review artifacts. Same child echoes accepted sentinels to stderr via fragmented writes/CRLF/long no-newline output, initialization metadata/notifications, malformed protocol output, JSON-RPC service error, is_error tool result and shutdown error. Initial, reconnect, cold hydration and wake all use the same frozen set and error policy despite changed defaults. No raw/known escaped private sentinel appears in these public diagnostic surfaces or unkeyed diagnostic hashes. Invalid/oversize diagnostics never publish prefixes or fallback raw; invalid/oversize transport refuses with bounded safe reason and zero child effects if that is the chosen contract. Arbitrary transformed tool content is not universally protected by exact literals; do not claim otherwise.

Short-literal assertions must distinguish exposure sourced from private inputs from coincidental identical bytes in declared public IDs/reason codes; literal absence of a one-character input from every public English message is not a meaningful secrecy oracle. If the contract instead demands literal absence there too, diagnostic fields must also be suppressed/sanitized to match it; do not silently apply a length exemption.
