WHY THE REMAINING TRANSITION IS COHERENT

1. Committed initial startup is handled as a real special state, not a fictitious
   Running epoch: full original startup plus PendingStartup0, zero registry debt
   and completed original host preparation permit its first suspension/closing1.
   ACK changes it to Suspended0, so stale startup ACK cannot subsequently issue
   Running0. A later independent Continue opens the normal next epoch. Missing/
   conflicting/uncommitted journal is not used as an empty proof.

2. Continue2-origin/Stop3 uses a CURRENT control3 no-dispatch proof rather than
   rewriting epoch0 closing1. Frozen canceled opening2 cannot receive ACK or
   reservations. Typed OpeningCanceled plus fence/snapshot3 and actual raw receipt
   are verified in a separate registry CAS. No epoch2/capability exists. Both
   prior genuine terminal set/seal1 and current canceled-opening receipt3 remain
   required; RunContinued2 alone is display/history data, not dispatch authority.

3. Continue4 explicitly validates the current Stop3 association and old original
   terminal proof. This provides the missing legitimate next transition without
   overwriting the old seal, reviving canceled2 or leaving Stop3 permanently pending.
   Repeated later canceled openings link their immutable actual control receipts,
   with complete bounded-paged ancestry checking rather than numeric assumptions.

4. Caller loss, origin/journal commit before registry ACK, conflicting raw bytes,
   and newer current control all have meaningful replay/refusal outcomes. Historical
   receipt repair does not overwrite newer operator decisions. Original runtime-
   independent owner must retain pending authority/receipt until ACK or durable
   Attention; disk-full does not release it. Those physical ownership guarantees
   remain StageB evidence, not consequences of this storage design alone.

5. Startup not committed has a distinct private NoStartupDispatch issuer: surviving
   original unconsumed startup-command slot, completed preparation, zero obligations
   and no admitted execution. A newly claimed lease, empty DB, missing PID or failed
   callback cannot issue it. Consumed/in-flight/crashed/unknown transaction states
   require original receipt inspection/repair or Attention. This is not native
   NoChild and cannot settle any created child/domain/request debt.
