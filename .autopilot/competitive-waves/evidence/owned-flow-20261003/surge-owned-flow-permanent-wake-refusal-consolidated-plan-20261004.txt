Storage creates the single lease before actor spawn and keeps its own original clone across spawn success/failure; spawn_writer receives a clone, and writer_loop explicitly holds it across every command/await with drop at final exit. Producer/actor spawn failure/runtime destruction and actual lease Arc counts alone do not substitute for physical lock contention/real SQL sequence observation.

Concrete one-purpose owner API and ownership
Proposed private work_items/owned_flow/refusal_owner.rs (not a general executor). RefusalSupervisor owns at most8 live slots/threads, each fixed512KiB stack, fixed public thread name. Slot contains the ORIGINAL Arc<StableOwnershipGuard>, independently validated receipt draft, DeliveryResources { cloned existing registry pool, home/path identities, Arc<Clock>, Arc<ActiveWriters> }, state {Preparing, Ready, Committed, Aborted, CommitUnknown, Delivering, Delivered}, completion condition and actual JoinHandle tracked until joined. Guard created before association validation and cloned only into this exact slot; never reconstructed from receipt/token. A process-wide registration index retains Arc<Slot> as an outer owner through thread execution and panic, independently of caller futures and channel messages. Slot/registry poisoning is fixed fatal containment without unwinding the sole owner.
RefusalSupervisor::reserve(slot)->Result<Reservation,FixedOwnerError> is synchronous/nonblocking capacity admission. It registers the outer slot before thread creation; thread creation consumes only an Arc clone. Spawn failure rolls back registration while the caller still holds the original guard, and no registry mutation is committed. Spawned worker signals Ready without registry/DB work; reserve waits for that exact ready handshake with no supervisor/slot mutex held while waiting. Eight-slot exhaustion returns Busy before any refusal write. Completed slots remain indexed until their actual handles are joined; reclamation joins outside every mutex.
Reservation::publish_committed(key,hash) is synchronous after the registry transaction commits. It flips the pre-existing slot state and wakes the worker; only Arc clones/metadata move, no sole owner passes through channel send or cancellable spawn. Reservation drop before confirmed commit signals Aborted, worker releases its clone and is joined while caller retains its guard. Ambiguous SQLite commit errors become CommitUnknown: worker checks the exact immutable key/hash; confirmed absence permits Aborted, exact durable row permits Committed, inaccessible/contradictory storage retains ownership and no ACK. No worker waits for the caller's commit under a mutex held by the caller. Caller return/cancellation cannot remove the supervisor's registered outer owner.
The full worker body and all synchronous owner-sensitive operations use the exact shared surge-process::owner_panic contract above. Worker panic fatally aborts with the outer slot alive; it is not a recoverable retained-worker state. No second hook, raw panic payload destruction, detached ownership or general StageB/native dependency. This consolidated proposal itself still requires independent precode acceptance before any source change.
