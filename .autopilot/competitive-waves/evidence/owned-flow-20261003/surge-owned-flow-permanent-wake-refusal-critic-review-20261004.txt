MUST-FIX 1 — Section5 deliberately leaves the cancellation-independent worker seam unreviewed; make this a concrete prerequisite, including cold recovery and shutdown.
Current daemon runtime_shutdown.rs owns only the Tokio runtime and calls surge_mcp::shutdown_children_and_join after consuming it. There is no refusal worker owner, registered outer slot, supervisor, or synchronous journal-delivery capability. The write map omits runtime_shutdown/main construction and terminal teardown even though the required behavior depends on them. Current WorkItemStore::claim_owned_flow constructs Arc<PreparationLock> only after successful association/claim-token commit. The new refusal branch needs the original guard moved into a real outer owner before its different transaction commits, with no guard-release gap on failed thread creation/handoff/panic/cancellation. Refused returning a nonSerde capability alone does not establish that owner.
Specify actual private types, creation/retention sites and methods: a bounded host supervisor surviving runtime consumption, reservation and exact original-Arc slot, synchronous install/ACK before transaction commit, committed-versus-rolled-back publication state, wake notification after commit, retained slot when worker panics, and terminal join ownership. Avoid a worker holding the slot while waiting for registry commit under a lock the caller is holding. Pin thread/slot caps, full-capacity behavior before mutation, retry pacing and how completed reservations are reclaimed. Pin the synchronous production journal opener/append helper and lock ordering; existing writer::handle_command AppendEvent owns the real transaction/sequence/view update, but is inside the Tokio actor. Factoring that closure is feasible; invoking async RunWriter or an ad hoc SQL writer does not meet this contract.
Cold delivery needs its own narrowly typed reacquisition path from independently accepted operation/launch identity: existing claim_owned_flow calls association and stored() and therefore cannot reacquire a rejection whose association still mismatches without attempting the forbidden normal claim path. It must leave the old claimant token unchanged, authenticate the original stable object, and operate only on the already committed informational receipt. Startup outbox drain must precede any launch-capable recovery/router/wake subsystem. Include this entry and lifecycle construction in the write map. Decide the terminal policy for permanently unavailable disk/journal: an indefinitely retained guard cannot also have an unstated finite join guarantee; a deliberate terminal wait or explicit process-termination policy must be stated honestly, without detached handles or a successful-delivery fiction.
Required evidence: real second-process lock contention while async waiter is cancelled and runtime is gone; worker publication rollback/failure/panic; shutdown owner inclusion; cold receipt delivery with the unchanged damaged manifest and unchanged claim token.

MUST-FIX 2 — Sections2–3 need explicit ordered independent-coherence predicates and a bounded parse-failure scope.
Current association() mixes current mutable item workspace/archive/accepted revision/generation with source/receipt/inputs checks. In particular it compares inputs.workspace against item.workspace and compares item.workspace against source.workspace. A legitimate current workspace or control edit must be classified as obsolete/current-permission refusal before a manifest mismatch can become a permanent accepted-data refusal. Pin the comparison baseline to independently validated original accepted source.workspace and receipt.workspace_owner, after authenticating accepted revision/origin hash, attempt binding/graph/config, receipt run/item/operation/binding and original launch identity. First establish independent accepted coherence; if source/receipt/attempt are incoherent, do not use one damaged record as a tie-breaker to blame the manifest. Then establish exact current permission; only after those checks can the typed manifest mismatch authorize Attention. The transaction must distinguish ambiguous independent corruption from this bounded proven mismatch without parsing Conflict text.
StoredLaunch::stored currently deserializes inputs_manifest together with source and receipt before the stable guard is acquired. Invalid JSON or a validating-constructor failure can therefore occur before the proposed outcome exists. Explicitly state that malformed/deserialization-invalid manifests remain a separate unhandled negative in this amendment, with no claim that all permanent input corruption now reaches Attention; or introduce a reviewed raw-record/independent-identity loader and typed malformed-input path. A test that mutates a structurally valid binding is not proof of malformed manifest coverage. Do not convert arbitrary SQL/serde/I/O errors into this fixed reason.
Required evidence: valid independent authority + manifest-only wrong workspace/binding gives Attention; a legitimate mutable item workspace/edit or newer control does not; independent receipt/source mismatch is conservatively distinct; invalid manifest JSON honestly exercises the selected scope rather than failing before a supposed permanent-state oracle.

MUST-FIX 3 — Sections3 and6 must preserve legitimate existing due-cycle lineage, rather than make exact matching a permanent retry trap.
Current resume_parked_work_item obtains claim, reads current Suspended control, then reserve_due_quota_wake selects the oldest due cycle and deliberately invokes rebind_recovery_control when its generation differs from the current control. That production method has real policy predicates: exact original cycle/revision, prior control +1, current Suspended/Executing identity, matching confirmed capacity fence, and preserved selected candidate observation or planned exhaustion. The new wake entry occurs before this rebind. Requiring cycle.control_generation == current control.generation unconditionally would return Obsolete on every subsequent tick for an otherwise valid transferred capacity cycle, suppressing both healthy execution and the permanent-mismatch diagnostic. Accepting arbitrary mismatches would instead bypass the existing route policy.
State explicitly whether the new entry accepts the exact observed pre-rebind cycle plus current control, validates the existing transfer predicates without mutation on refusal, and leaves the successful Ready path to perform the existing rebind/reservation; or performs an equivalent approved rebind in its single transaction after valid association. Preserve the policy and the original source-revision/wake identity. Do not mutate cycle lineage on the rejection path merely to manufacture a matching key. An actual operator race since selection remains Obsolete with zero mutation; an already legitimate confirmed transfer present at selection must have a productive positive path.
Required evidence: genuine planned/exhausted capacity transfer under a later valid Suspended control, paired uncorrupted successful automatic wake and manifest-only refusal, plus a manual/non-capacity/newer incompatible control case with unchanged receipt/route policy. Test more than equality of freshly created control/cycle generations.
