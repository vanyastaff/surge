T25 bounded amendment: permanent immutable-input association refusal at quota wake
Disposition: proposed; no production behavior authorized by this document.

1. Observed baseline and limits
Actual integrated session 27730 exited101 (14 PASS,2 FAIL). Offline ManifestBinding corruption reaches claim_owned_flow association() while the original FlowLaunch guard is held, before SQL claimant token mutation. The generic Conflict returns before reserve_due_quota_wake; WakeScheduler retries, and the current attempt/control remain Suspended. This is not a missing child cleanup proof and must not be repaired by Closed/domain records. A separate once-tick lasting-state oracle will establish the permanent-state RED without the secondary resource failure.

2. Typed classification
Split immutable accepted data coherence from current permission in owned_flow/launch.rs. Only inputs.operation/run/binding/workspace/workspace_owner mismatches against the independently validated accepted source, original receipt and current attempt produce WorkItemError::OwnedFlowInputsAssociationMismatch (fixed Display, no String/source/private payload). Archive, changed active run/revision/generation, canceled intent, Stop, inactive attempt, lock replacement/busy and transient SQL/I/O remain distinct existing refusals. Do not classify Conflict text. No constructor/deserializer capability is minted from a manifest.

3. Single exact wake entry
Add WorkItemStore::claim_for_owned_flow_quota_wake(expected_attempt, expected_control, expected_due_cycle), returning a typed private-host outcome Ready(original claim), Refused(retained rejection capability), or Obsolete. Legacy tasks retain their existing claim path. The daemon reads the existing due-cycle/control snapshot only to select this entry; those reads grant no authority. In one IMMEDIATE registry transaction under the same original FlowLaunch descriptor guard, reread the accepted operation/launch identity, accepted flow origin/source/receipt, item/attempt, latest control, selected due cycle and immutable first manifest. Verify guard identity before any write and again before commit. Require exact expected attempt binding and control operation/generation/state, active unarchived item, started accepted intent, Suspended attempt+Suspended control and same due unclosed cycle/source revision/wake identity. A changed/newer operator action, cycle, archive or assignment yields Obsolete with zero mutation. A valid association yields the normal claim token and existing reservation path. A manifest mismatch alone yields Refused without changing the prior claim token or reserving Continue/provider opening.

4. Refusal transaction and receipt
Persist a unique immutable refusal receipt keyed by (run,attempt_generation,control_generation,invocation,cycle_generation,source_revision,wake_identity), including original accepted operation, binding, control operation and fixed reason OwnedFlowInputsAssociationMismatch. Two small registry tables separate invariants: owned_flow_wake_refusals holds immutable key/payload/hash under UPDATE/DELETE-refusal triggers; owned_flow_wake_refusal_outbox holds a constrained mutable delivered_event_seq acknowledgement referencing that immutable key/hash. A delivery acknowledgement may advance only NULL -> the actual observed journal sequence; the immutable row never changes. No generic execution authority ledger. Atomically insert the first receipt, update the exact attempt and current control to Attention with fixed diagnostic, increment item version, null the selected cycle wake_at and registry runs wake_at_ms only while its status is Parked. Keep Parked as a coarse nonterminal status; do not falsely set Failed/Running/Completed or alter suspended journal/snapshot/cleanup evidence. Existing operator receipt/history and accepted inputs/source/intent remain immutable. Attention is authoritative immediately; journal delivery failure cannot retry execution.

5. Honest journal delivery and ownership
The registry transaction is not claimed atomic with a separate WAL journal. Its immutable receipt is a transactional outbox. Add informational OwnedFlowWakeRefused{receipt} with the required schema migration, pure validated receipt type, exhaustive projection no-op arms; it grants no resume/closure authority. Refused carries a nonSerde host capability retaining the very same Arc<StableOwnershipGuard>. It must not be transferred solely into a cancellable Tokio task. Before the registry commit, a bounded host-owned std worker reservation is established and a clone of that exact guard is retained in an outer slot; publication transfers only an Arc clone of that slot, not its sole guard owner. Worker acceptance acknowledgement precedes release of the synchronous caller's slot owner. Failed thread creation, closed queue, panic or failed handoff leaves the original outer owner retained; no transaction may commit a promise of a worker that does not exist. Cancellation of the IPC/wake task cannot drop the worker's guard. The worker belongs to the terminal host join barrier (after the main Tokio runtime is consumed); no thread handle/guard is detached or omitted from shutdown. This requires a small concrete runtime-independent refusal-worker design review before implementation, rather than borrowing the MCP tracker without an approved API.
The worker performs synchronous journal delivery using the real per-run FileLock and factored existing writer append/sequence/view logic, not a test SQL writer or an async task on the host runtime. It validates independent original accepted receipt, accepted flow artifact/hash and unique actual startup run/binding; it intentionally does NOT demand that the corrupted inputs manifest agree with the original association. That mismatch is the refusal's evidence, never a trust input. Scan the actual journal for the exact receipt key+hash; conflicting duplicate refuses. Append durably, then acknowledge the exact event sequence in the separate outbox row. Hold the original guard and per-run writer lock through both operations. Never acknowledge before the durable event; crash-after-append deduplicates. Newer operator state is not overwritten by historical receipt delivery. Persistent I/O/writer-lock refusal retains the worker guard and pending outbox rather than claiming delivery; bounded active reservations prevent unbounded workers. Process death necessarily releases OS handles, so cold recovery reclaims the persisted original launch object identity before retrying the receipt, while Attention continues to prohibit effects. No synthetic claim/Closed/cleanup ACK. All physical launch branches remain blocked by Attention and current control.

6. Tests before final acceptance
Real once-tick cold manifest-binding baseline observes original Suspended/current control after an actual fixed association refusal; zero new provider/MCP recorders and unchanged claim token. GREEN requires durable Attention, exact fixed receipt and eventual journal event; many ticks/restart cannot reserve/open/spawn, receipt remains identical. Positive uncorrupted Empty and populated initial twins remain actual production paths; populated cold closure acceptance remains OPEN. Real barrier operator Stop/archive/new control between selection and IMMEDIATE reread must leave the newer decision/receipt untouched. Busy lock/transient reader/database errors preserve retry and do not create a refusal. Cancellation after rejection transaction retains original guard through journal worker, proved by a second-process lock oracle; crash after transaction/before event and after event/before delivery ACK recover one identical receipt/event. No schema trigger weakening outside isolated offline corruption fixture.

7. Secondary thread-resource finding: separate follow-up, no behavior yet
Storage::work_items clones its registry pool; it does not create a pool per claim. WakeScheduler::read_snapshot does build a fresh RunReader pool each tick. Pinned r2d2 0.8.10 config.rs250 defaults to a new three-thread ScheduledThreadPool; lib.rs380 schedules a delayed reaper with a Weak pool. scheduled-thread-pool0.2.7 builder.rs19 defaults to CompletePendingScheduled; lib.rs394-410 waits for pending future deadlines after Drop. Thus fast repeated refused wake ticks accumulate live scheduler workers temporarily, independently of any executable child leak. The existing escalation module documents this construction cost. Do not hide it by slowing the corruption test or suppressing errors. Proposed separate bounded pool-resource amendment: Storage-owned shared reader scheduler (workspace-managed scheduled-thread-pool dependency), bounded fixed workers reused by all fresh reader pools, preserved read-only DB connections and lifetime/pragmas; requires its own actual repeated-reader resource oracle and focused review before behavior. No current change to reader construction is authorized here.
