1. Windows routing / stable ownership

Every descendant creation, collision-only reopen, directory name check and final lock lookup is relative to the actual retained parent handle, with exactly one checked UTF-16 component. RootDirectory-relative naming is an actual NtCreateFile contract. OBJ_DONT_REPARSE puts refusal in name parsing; FILE_OPEN_REPARSE_POINT and actual attribute/type checks remain required. Parent reparse mutation cannot substitute a different ancestor through a concatenated absolute pathname because no descendant open uses such a pathname. Root bootstrap is restricted to the parsed OS volume/share root, with actual root identity and type checks; arbitrary device, pipe, drive-relative and alternate-stream names remain rejected. The full chain of volume/128-bit IDs plus names, type, reparse and delete-pending observations remains independently checked before and after locking/finalization. No-delete share excludes ordinary rename/delete while retained. Attribute access exceptions are real and must not be described as denied by sharing.

Microsoft documents the RootDirectory contract and exclusive FILE_CREATE / existing-only FILE_OPEN dispositions: https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile . Microsoft’s current English OBJECT_ATTRIBUTES table omits OBJ_DONT_REPARSE; its official Chinese translation explicitly documents refusal with STATUS_REPARSE_POINT_ENCOUNTERED: https://learn.microsoft.com/zh-cn/windows/win32/api/ntdef/ns-ntdef-_object_attributes . Sharing exclusions and attribute-access exceptions: https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew . This source discrepancy should not be hidden by claiming the currently retrieved English table contains that flag.

Only exact STATUS_OBJECT_NAME_COLLISION from FILE_CREATE permits FILE_OPEN with the same checks; no FILE_OPEN_IF, overwrite, truncate, invalid-object retry, unlink, adoption or path fallback is authorized. Both independent same-process handles and cross-process owners must converge on the same persistent OS lock; File::try_lock is the lease, not sharing flags or SQL TTL. Changed persisted ancestor/lock identity after owner death yields conflict. True process termination and lock release authorize reclaim of the original immutable operation, not a new snapshot/allocated owner. Task key compatibility and flow-operation namespaces remain mandatory.

2. Unsafe SDK / output ownership profile

Inspected installed windows 0.58 generated NtCreateFile, OBJECT_ATTRIBUTES, IO_STATUS_BLOCK, UNICODE_STRING and constant declarations. The plan's Wdk_Foundation, Wdk_Storage_FileSystem, Win32_Storage_FileSystem, Win32_System_IO and Win32_System_Kernel feature choices match those cfg/type seams. This is ntdll's user-mode NtCreateFile despite its generated Wdk module location; handwritten ABI declarations are unnecessary.

The exact authorized synchronous profile uses FILE_SYNCHRONOUS_IO_NONALERT and SYNCHRONIZE. Directory opens use FILE_READ_ATTRIBUTES | SYNCHRONIZE (not generic data/append/execute rights); regular read/write lock opens use FILE_GENERIC_READ | FILE_GENERIC_WRITE. Type constraints and no-follow options accompany both dispositions. OBJECT_ATTRIBUTES.Length uses SDK size_of; pointer-bearing structures and checked byte-count UNICODE_STRING storage stay valid throughout the call. The authoritative Unicode length unit is bytes: https://learn.microsoft.com/en-us/windows/win32/api/ntdef/ns-ntdef-_unicode_string .

Use initialized output slots; inspect the returned NTSTATUS before output interpretation. Only a completed successful call with a valid returned owned handle transfers it exactly once into OwnedHandle then File. Borrowed RootDirectory is never closed or adopted. No OBJ_INHERIT, duplicate lock handle or manual early unlock is authorized. On failed calls close only results the API contract actually establishes as owned, not arbitrary output bits. SDK metadata result buffers must similarly be initialized or read only after success with their correct SDK sizes/classes.

Microsoft specifies synchronous non-alert I/O with SYNCHRONIZE and states the reparse-point open returns success or error; no async/incomplete profile is authorized. https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-zwcreatefile and https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile . Do not reduce the invariant to NT_SUCCESS on any positive status: STATUS_PENDING is incomplete. If implementation admits a pending operation, output/pointer storage cannot be dropped merely because it is rejected as an ownership result; completion must first be settled. The plan's synchronous-only lifetime requirement excludes that implementation. IO_STATUS_BLOCK's authoritative pending/completion rule: https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ns-wdm-_io_status_block . Rust documents exclusive/nonblocking Windows locking and owning-handle closure release: https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock .

3. Empty MCP authority / no-default fidelity

Empty is not a caller boolean, plaintext hash or a replacement for private-input authentication. It is host-produced after one actual effective-list resolution and atomically binds the operation/request receipt, accepted immutable attempt, allocated item/run/workspace owner, FlowOrigin graph/raw-prompt relation and frozen config. Explicit(empty) and HostDefault-resolved-empty remain distinct accepted selections. Caller input may request an empty selection but cannot create the private non-Serde validated capability.

Actual seams checked: engine/work_items.rs::pinned currently validates the launch claim and hydrates the accepted origin/config; validate_resume compares startup config, workspace/prompt, unique WorkItemAttemptBound, graph and accepted artifacts. This existing structural trust is suitable only within the explicitly trusted host-store/process boundary. It does not cryptographically authenticate an arbitrary SQLite writer. The amendment correctly requires stronger applicable pending-first-start or continuation/control predicates before effects; validate_claim alone is not sufficient. Journal absence is initial pending-intent authority only. Unique flow startup snapshot/binding and empty RunStarted public list must match the accepted attempt for cold wake/resume.

Existing engine.rs resolve_run_mcp_registry has an empty-list global fallback; resume also overwrites public MCP fields from RunStarted. Both are named concrete seams requiring the validated owned snapshot branch. The Empty branch must directly produce no registry/servers and bypass fallback and public-field overwrite at first dispatch, cold resume and wake. Missing/duplicate/mismatched startup events, binding/selection transplants, nonempty public lists and wrong control refuse before any executable effect. This excludes wire/config forging and reorder/default-swap attacks under the stated host-owned persistence boundary; unrestricted host-store mutation remains outside that claim.

Private snapshots retain full HMAC purpose/schema/operation/request/item/run/workspace/server/list-order/manifest/transport binding, existing-key-only hydration and immutable literal command/args/env. Private key/object corruption or disappearance is never reclassified as Empty; populated frozen HostDefault does not become Empty when live defaults disappear. Provider inherited auth is not captured. RestrictedPrivateInputs remains unsupported on Windows and rejects before sensitive capture or executable writers. StableOwnership availability supplies no secret-store capability.
