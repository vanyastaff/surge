2. Current actual protocol, including failure windows
refusal.rs: pre-reserves actual std worker with original guard, Ready before write
transaction; validates independent original startup outside registry write txn.
Mismatch transaction commits immutable receipt+pending outbox+Attention and clears
wake. Publish follows tx.commit result, including CommitUnknown on commit error.
A crash after registry commit and before publish leaves durable pending outbox,
recoverable on fresh process; it does not create a dispatch claim.

refusal_owner.rs: Slot retains Arc<PreparationLock>, pooled registry resources,
clock and SAME ActiveWriters Arc independently of Tokio/caller. Registry entry is
registered before thread creation, actual handle published, max8 owners. Unpublished
reservation aborts and joins; published drop does not abort delivery. Worker retries
errors every100ms and keeps acquired JournalOwner between attempts. A proven absent
receipt only resolves uncertain commit; inaccessible/invalid DB is Err, not absent.
Actual guard remains in registered slot even when worker has finished until join.
Close refuses new admission before teardown; join waits actual handles. Permanent
unavailable evidence can intentionally hold shutdown until repair/owner resolution;
timeout is not proof that a retained owner may be discarded.

refusal_delivery.rs:75–160 checks guard+immutable receipt+independent binding before
acquiring SAME normal writer slot and existing-only .lock. Journal READ_WRITE open
has no CREATE; missing file/dir errors retain slot original guard, and any acquired
lease. Event append commits at139 before separate registry ACK. Retry validates
startup anchors and scans exact lineage; existing exact receipt event reuses its
sequence. Duplicate/conflicting same-lineage event is rejected, not silently ACKed.
After event commit second journal transaction verifies exact durable occurrence;
registry ACK validates key/hash and any prior sequence, then commits at158.
If final read-tx commit fails after ACK, retry is idempotent. Neither append return
value nor EOF nor worker timeout acts as authoritative delivery.

0030 receipt update/delete and outbox key/hash rewrite/delete are blocked; once ACK
nonnull it cannot change or clear. Outbox FK binds exact receipt key+hash. This is
informational delivery evidence, not a provider/native Closed certificate.
