2. rmcp: required narrow pinned dependency amendment, not ACP-shaped guess

Public send_request_with_option allocates ID and then awaits internal tx.send
before exposing it. A check before calling it is stale at internal enqueue; the
caller can be canceled while blocked. Merely wrapping transport.send stops bytes
but fails the plan's BEFORE-SDK-enqueue current admission requirement.

Recommended minimal rmcp patch candidate, kept generic and unaware of Surge DB:
Peer::prepare_request(request, options) -> Future<Result<PreparedRequest<R>, ...>>
waits for an owned mpsc queue-capacity permit and allocates exact ID/progress token;
PreparedRequest::id() -> &RequestId;
PreparedRequest::enqueue(self) -> RequestHandle<R> consumes the held queue permit
synchronously, without an await. PreparedRequest remains opaque/non-Clone and
Drop before enqueue provably emits no request/cancel notification. Its enqueue
returns only after responder ownership is installed in the queue payload. Mirror
PreparedNotification for explicit cleanup notifications. No public JSON token,
caller boolean, serialized authority, or user-defined arbitrary proof callback.

Surge wrapper first has retained slot + durable reservation, awaits prepare,
binds exact ID, performs current EnqueueAdmission and calls enqueue synchronously;
immediately retains RequestHandle/rx in slot before outcome waiter delivery.
Queue permit exhaustion/connection shutdown before enqueue is a separate genuine
NotEnqueued path, not response cancellation. Existing methods preserve legacy
behavior by implementing prepare+enqueue internally; no blanket public API break.
ID allocation must not wrap into live/reused IDs: current AtomicU32 provider is
actually AtomicU64 -> i64 cast. Patch defines checked exhaustion/no reuse during
connection lifetime, including init's allocated ID and progress token.

Initialization requires an additional exact bootstrap seam. Recommended generic
client startup prepared-frame hook accepts actual typed initialize ID before
transport.send, and a separate initialized-notification occurrence. Hook invoked
synchronously after capacity/readiness and before enqueue. Host private constructor
provides bootstrap reservations before .serve; hook cannot manufacture authority.
Alternative replacing the entire rmcp client handshake is larger and risks divergent
protocol negotiation; do not silently choose it. Both direct client initialization
and normal Peer operations must use the same private owner table. Incoming callback
response/error, explicit cancellation, notifications and SDK-internal frames require
separate typed origin binding at their actual creation seam; unmatched owned frame

3. Physical frame transport: replace owned AsyncRw use, preserve legacy path

Proposed private FrameEnvelope contains occurrence key, connection incarnation,
direction, exact typed RPC ID/notification origin, immutable complete serialized
bytes INCLUDING newline, private owner slot, and cursor. Memory only: no payload,
prompt, env, argument, response, or capability bytes in logs/ledger. Protocol JSON
never carries FrameAdmission. Serialize once; do not hash one buffer and send another.
ACP source already exposes whole outgoing frame; rmcp custom Transport<RoleClient>
sees typed complete message at send. Owned path must not delegate physical writing
to opaque FramedWrite. Legacy/unowned AsyncRw remains unchanged unless separately
verified. Bounded line decoder must preserve the locked rmcp compatibility policy
or explicitly reject unsupported inputs; no raw-frame debug diagnostics.

A generic AsyncWrite wrapper checking before poll_write is NOT an after-writable-
wait gate: inner poll_write may itself wait for readiness/buffer data. Candidate
concrete Unix implementation uses original owned stdin/stdout descriptors in a
single nonblocking pipe worker: safe nix fcntl O_NONBLOCK (existing fs feature),
PollFd/poll readiness (new explicit nix poll feature if required), safe write/read.
No native domain factory/kill/wait proof is created. Poll writable, then synchronous
current admission/revalidation immediately before actual write syscall. No await
between gate and syscall. EAGAIN with 0 bytes retains exact frame, retries only
with a fresh current check; never consumes a second dispatch occurrence. Registry
FrameAdmission records the one occurrence; private retry state certifies no prior
bytes, revalidates current right on EVERY attempt. Positive write increments cursor;
first >0 byte makes all later cancellation/error PartialFrame/Unknown, never NoEffect.
Frames cannot interleave. After first byte Stop forbids subsequent frames; owner may
finish remaining bytes of this already admitted frame or close transport under an
explicit frozen policy. This policy must be chosen in the pinned plan, not guessed
in implementation; either leaves operation/domain debt until genuine terminal proof.

Use bounded coordinator/IO slots and bounded bytes BEFORE SDK enqueue. Pipe fullness
cannot block worker forever: readiness loop also services control/read-side, bounded
backpressure and shutdown. EOF/WriteZero/error/runtime loss is observed by retained
owner, not by detached caller. Descriptor closure is private original-owner action;
no numeric PID cleanup, no second child waiter. Windows physical IO is a separate
unresolved seam; don't claim Unix poll proves Windows overlapped-write semantics.
Generic test AsyncWrite remains useful for cursor properties but cannot establish
real first-byte behavior. If this Unix IO amendment is rejected, byte-gating seam
is BLOCKED, not satisfied by checking once before write_all.
