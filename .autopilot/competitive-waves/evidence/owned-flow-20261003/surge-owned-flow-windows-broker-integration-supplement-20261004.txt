1. Selected placement: preserve actual local ownership, avoid remote SDK invention
Windows native owned run is hosted by an Engine/TrackingContext INSIDE the original
broker process, reusing existing owned_flows acceptance, work_items host, engine,
ACP/rmcp SDK and accepted B coordinator. Main daemon forwards typed original user
requests and reads journal/query DATA. It does not host a second engine, SDK,
RunWriter or frame parser for that run. Broker is sole birth/wait owner and owned
run host. This replaces base sections2/6's unresolved remote journal sink placement
with a local sink; no remote RunWriter trait, raw stdio relay or SDKresult RPC.

Why selected: actual RunTaskParams.writer is concrete RunWriter (run_task.rs52);
engine start_run_writer509 creates/opens actual writer; many helpers accept that
concrete type. Remote RunWriter/SDK outcomes would add copy-budget and authority
surfaces. Moving existing owning host composition leaves those APIs and local
non-Send SDK retention intact. This is an explicit affected dependency closure,
not an assertion current constructors support broker mode or already work.

The broker accepts owned request BEFORE OwnedFlowPreparation.finalize returns its
actual initial WorkItemLaunchClaim. The initial guard is therefore minted in broker,
retained SAME Arc by supervisor/engine/B coordinator/native registration, never
created in daemon and serialized/transferred. Configured WorkItem Start likewise
executes preparation/finalization/claim in broker. Actual journal actor+wrapper
share SAME Arc<WriterLease> inside broker. Daemon receipt has DATA IDs only.
Broker never reacquires initial claim to simulate handoff. Native original objects
and local B SDK/journal responsibilities now survive daemon death together.

Daemon disconnect cancels only its authenticated frontend session; native broker
closes future dispatch, freezes/drains/stops original responsibilities, and parks
under accepted authority; it retains runtime/SDK until exact safe drop/cleanup.
It does not keep dispatching silently under old frontend authority. Controlled
broker runtime teardown uses accepted std coordinator/sole owners and journal
terminal protocol(b); process death is Unknown. A new daemon reconnects SAME broker
and original journal/claim, not open_run_writer/claim. If actual broker died, no
fresh owner cold-positive. Broker idle exit only after all old slots/records ACKed,
physical+wire+external obligations settled, and no accepted pending task authority.

New persistence module proposed work_items/native_authority.rs owns native binding
and NativeMutationAuthority. No daemon/MCP/ACP import. Storage facade factory uses
actual protected broker-home OS owner lock plus backend-issued verified current

(run,item,attempt_generation,opening_control,operation,recipe_hash,original
claim_token,broker_incarnation,domain_nonce,accepted_startup_identity). Original
association immutable; replacement prohibited until authentic final debt seal.
Current control/phase is separate typed mutable state, not rewritten origin.

Proposed public opaque NativeRunRegistry handle is broker-local, nonSerde,
nonClone of owner resources; it owns original claim Arc, home owner capability,
actual B coordinator and per-run serial native lane. It exposes bounded typed
request submission only; callers never receive private NativeMutationAuthority.
Internal NativeMutationAuthority<'lane> borrows a live lane guard, captures exact
owner/phase/current generation and mutation kind; !Send across actor turns,
no Deserialize, no arbitrary callback granting closure. Private check_native_in
inside SAME SQL transaction validates immutable native binding/current rows,
actual owner capability/held lane guard and typed allowed transition. No
separate pre-read satisfies it. Holding a lane does not itself prove physical
closure. All original receipt/claim/source/current generation validation retained.

Two mutation classes: authority/current control/new effect, and historical settlement.
First requires exact current lane state; second binds original occurrence and may
preserve newer control. Metadata-only discussion/PR and usage SQL touch only their
columns and cannot invalidate current physical gate. Item debt index covers prior
native attempts even if active_run is NULL. Admission must check that index in TX.

Broker lane has one proven order for native authority transaction commit and
physical dispatch. Final physical write/Resume occurs after all waits, exact current
B gate, then immediate syscall without await. All native authority mutators commit
ONLY that lane; no SQLite writer can commit newer Stop/edit/archive/claim in between.
No registry TX survives pipe readiness/journal wait/Resume/termination. Gate deadline
TOTAL20ms includes pool checkout+busy+SQL+revalidation (at most10ms checkout and
remaining deadline busy/SQL), never additive repeated20ms per helper. Finite failure
retains BornHeld/debt/Attention and no stale dispatch. A blocking syscall may delay
commit of later lane requests; they are reported pending, not already committed.
Read/control/Stop latches still serviced by B separate fairness/owner machinery.

Exact lane mechanism: one private std Mutex per original NativeRunOwner guards
current authority admission phase, not raw SDK handles or global storage state.
NativeLaneGuard is nonSend; it is acquired on whichever actual broker-local SDK
or native dispatcher thread performs this synchronous boundary. Fixed actor thread
identity is NOT required and nonSend SDK handles are never moved to another thread.
Actor receives typed mutation requests; its actual protected TX acquires this SAME
guard. ACP synchronous enqueue and rmcp OwnedPermit::send execute in the local SDK
thread through sealed owned adapter while holding SAME guard after current DB gate.
Native WriteFile/Resume executes with fresh SAME guard after every readiness wait.
No await/queue wait after grant and before enqueue/syscall; no stale reusable grant.
Try-lock contention defers and rearms rather than blocking IO progress; the gate
attempt's total20ms includes any admitted lane acquisition and storage work. SDK
prepare/channel-capacity/result waits occur BEFORE guard acquisition. Generated
reply serialization/outer-slot retention also precede guard. This is the existing
B last-boundary discipline extended to the shared native mutation lane, not a new
public Fn->proof API. Descriptor checks and registry predicates run each time.
No global slot mutex or live registry TX held during native syscall. Per-run guard
survives that immediate nonblocking write submission/Resume; unrelated run/control
and all read completion processing use separate progress machinery. Already-issued
overlapped IO is historical debt even if newer Stop acquires guard afterward.
This mechanism must be tested with actual SDK enqueue pause and actual SQL commit,
not only request queue ordering. Original policy read checks outside this protected
boundary are hints, never dispatch authority.
