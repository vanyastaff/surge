4. Native birth and retained ledger
Before OS effects reserve accepted B responsibility/delivery/cleanup capacity and
broker domain slot, validate original registry registration/current startup and
recipe, and install owner ledger entry. A slot is not released by timeout or lost
reply. Journal Startup/Pending0 and native launch intent must already have accepted
receipts; original startup receipt is not inferred from malformed/missing manifest.

Inside protected owner body, create UNNAMED Job with reviewed explicit security
attributes, set no breakaway/silent-breakaway and KILL_ON_JOB_CLOSE policy, own
stdio/attribute resources, then CreateProcessW with atomic JOB_LIST assignment,
CREATE_SUSPENDED|EXTENDED_STARTUPINFO_PRESENT|CREATE_UNICODE_ENVIRONMENT and pinned
recipe flags. The Job and ledger owner exist BEFORE successful CreateProcess.
No create-then-Assign fallback. On success adopt hProcess/hThread into existing
owner slot immediately, before fallible conversion, IPC ACK or journal await.
Store actual root identity via held handle; append immutable Birth DATA through
original journal sink. Lost Birth ACK leaves BornHeld+delivery debt, not permission
to retry CreateProcess. Same request identity+same recipe returns existing state;
changed identity/body is refusal. Child success after caller disconnect is retained
and stopped/frozen by original owner, never classified NoChild.

Broker ledger bound: initially 64 active domains globally/4 per run, matching B
native-root reservation ceiling; no eviction of Unknown. Completed unreconciled
receipts also retain slots until exact durable ACK. Queue 64 control envelopes,
max 64KiB each; private recipe payload <=256KiB with checked UTF16/length ceilings;
initial global queued recipe budget16MiB. Native recipe/control budgets are
ADDITIONAL explicit pools, not silently charged twice against wire lanes. Admission
returns Busy before effects when full; Stop/terminal signaling uses preallocated
per-domain latch and cannot queue behind recipe/capture saturation. Ledger has one
owner and bounded retained records, not one new unbounded thread per message.
Dispatcher, root wait and capture progress must not mutually block on SDK delivery.
Native OS wait/cleanup may remain indefinite; queries/timers are wakeups, never
capacity forgiveness. Final byte accounting and worker count need review with B.

5. Current Release/Stop gate and race semantics
Selected serialization model: ALL control commits that affect native runs route
through the ORIGINAL broker per-domain host lane; daemon/UI/Telegram/wake/intake
may request intents but may not separately commit a newer Stop then send stale
Release RPC. Broker facade applies existing transactional control predicates using
WorkItemStore, independently accepted startup/claim/recipe/epoch and journal
receipts. All non-native control paths remain existing behavior. Missing broker
means Attention/Unknown and no new native dispatch, not registry-only Continue.

At lane dequeue, check current registry control+accepted origin and durable Birth/
launch intent. Reserve one-shot dispatch ID tied to original opening generation.
Commit dispatch-intent journal receipt using B finite gate without holding registry
TX across a pipe wait. Revalidate exact current authority in a short registry TX,
release connection, then execute ResumeThread immediately in SAME serial lane.
Stop and all native control writers cannot commit between this final revalidation
and syscall dispatch because their committing lane work is serialized, not merely
because callers promised to check. Native syscall may block that domain lane;
new intent is requested but not represented as already committed Stop. This is the
explicit linearization boundary, not OS/SQLite atomicity. Other registry mutation
that can invalidate launch authority (workspace/revision/archive/delete/claim
replacement) must acquire this same native barrier before its commit or refuse
while native effects admitted. Enumerate ALL such mutation sites before source;
a missed bypass is a blocker, not accepted TOCTOU. Cross-run lanes stay independent.

ResumeThread prior suspend count1 -> released successfully;0 -> unexpected already
running, >1 -> still held, MAX -> failure. Every unexpected result consumes this
permit and retains actual Birth/Unknown; never repeated decrements with same permit.
After syscall append outcome with original dispatch identity. Lost ACK/query must
reconcile broker state and historical receipt, never ResumeThread again. Stop
queued before Release admission cancels it, freezes spawn frontier and terminates
born held root/Job. Stop after Release admission owns running debt, terminates
original Job and collects actual terminal evidence. Newer Stop never rewrites old
opening/Birth/release origins. Accepted no-dispatch Stop only when exact unconsumed
startup/dispatch evidence proves no child; post-birth zero target instructions is
NOT NoChild. Repeat Stop is idempotent observation of same original responsibility.

Storage/lane enforcement is a required structural API, not a routing convention.
Propose persistence NativeMutationAuthority with private constructor bound to live
broker registration/current lane guard; native-bound mutation methods require it
and independently verify registry native-owner binding inside their actual TX.
Existing generic Store mutation entrypoints must reject native-bound runs unless
using that authority. Daemon Stop/edit/archive/delete/workspace/revision writers
send broker requests and wait for its ACTUAL transaction result; they must not
precommit separately and then notify. Accepted historical receipt delivery remains
allowed only under its exact existing stale-origin predicates, never a new effect.
Prepare a complete mutation call-site map and source-backed bypass counterfactual
before source permission. A callable direct registry mutation bypass defeats this
design even if every happy-path daemon handler forwards requests correctly.

All registry reads/revalidation/receipt gates retain accepted B TOTAL finite DB
gate budget20ms, including pool checkout, busy wait and SQL; no resetting the
budget at each helper or introducing an unbounded synchronous SQLite read in leaf.
Budget exhaustion before physical dispatch keeps held child/debt, no stale permit.
Registry TX is released BEFORE native syscall; native syscall/pipe/channel waits
never occur inside it. Control requests blocked by the in-flight physical lane
have not committed a newer control and cannot be presented as such. Actual tests
must pin both lane admission and actual TX commits; command ordering alone cannot
prove SQLite commit ordering. This does not silently replace B's final physical
gate: broker host invokes it in the exact native dispatch body after every prior
wait and validates SAME live owner/registration and accepted current predicates.
Only full reviewed persistence authority+all-writers map makes the serialization
claim implementable. Existing normal Stop/edit/archive paths are affected scope.

This requires a concrete persistence/daemon adapter amendment and actual newer-
control/race oracle. If maintainers reject broker-only native mutation routing,
alternative must supply an equally exact serialized gate; an async pre-read token
or a registry TX held across indefinite RPC is not an acceptable substitute.

6. Cold channel, authentication and physical authority
Create local named pipe with unpredictable per-incarnation name, FIRST_PIPE_INSTANCE
and PIPE_REJECT_REMOTE_CLIENTS, explicit DACL for intended logon/host principals,
individual read/write rights without granting clients FILE_CREATE_PIPE_INSTANCE.
Do not accept default ACL or generic-write shorthand. Connect challenge-response
uses fresh nonces and broker-issued secret stored only in private host credential
storage; never argv/environment/inherited target handle/public startup DATA/logs.
Verify GetNamedPipeClientProcessId/GetNamedPipeServerProcessId; open and retain
peer process handle, creation time, expected executable identity and token/logon
identity. PID check alone is not authentication. Peer identity failure/disconnect
revokes future dispatch; numeric handle or stale pipe path cannot reconnect.

Protocol v1: bounded versioned request ID + original registration + current control
intent; Hello/QueryOriginal/RegisterPrepared/Birth/RequestRelease/RequestStop/
DeliverRecord/AcknowledgeRecord/Freeze. Replay cache is ledger itself, not infinite
per-request set. Request IDs and generations use checked monotonic counters;
overflow closes admission. Only one authenticated controlling daemon lease at a
time; cold replacement takes a fresh session after actual old-peer death/revocation.
Broker launch uses explicit separate host-infrastructure ownership and no
parent-death termination policy tied to daemon runtime. No arbitrary Windows
creation flag is asserted to escape the runner's parent Job; actual parent Job
constraints and broker survival under daemon kill are capability preflight/tests.
If the runner kills the enclosing Job, broker loss remains Unknown. No broker
replacement/election on timeout while an old incarnation may still retain debt.
Daemon disconnect/actual death permanently fences that session, triggers native
freeze/Stop+capture drain, and leaves broker alive until original responsibilities
are physically terminal AND historical records durably acknowledged. Idle exit
allowed only ledger empty, no pending bytes/outcomes, closed admission and explicit
host termination acknowledgement. Unknown/unacknowledged debt prevents idle timer
exit. Broker fatal abort/OS kill cannot publish proof; KILL_ON_JOB_CLOSE requests
local termination but its success is not a durable original-domain receipt.
Native ledger retains original Job/child state while channel disconnects. No
arbitrary root PID adoption, OpenJobObject name lookup or second broker bootstrap
may resolve pending original debt.

Cold daemon queries same live broker incarnation, actual original ledger/hash,
held original Job, root terminal/live evidence and pending B delivery. It validates
original accepted attempt/workspace/journal/startup independently, reconciles exact
historical records under reviewed stable lock recovery WITHOUT rotating original
claim token, then may seal or dispatch a newly accepted Continue. It never calls
current claim_owned_flow() merely to obtain that property. Lost/replaced broker,
object/machine mismatch, damaged authority or lost pending record -> Attention/
Unknown with retained workspace, not fresh owner or imported JSON closure.

Cold IO policy: daemon death closes future provider/tool dispatch, broker freezes
native birth admission and requests original domain termination, while B capture
retains all already incoming frames and cleanup outcomes. Cold resumes ACP/session
only AFTER full native+wire+external settlement and accepted Continue, with same
original run/attempt/workspace/journal and stored provider sessions. Live stdout
cannot be handed raw to a replacement SDK before B capture/pending frame sealing.
Broker frame proxy must run accepted exact B scanner before any daemon SDK decode;
not transport pass-through that loses capture on daemon crash. Journal append sink
is a capability protocol to original actor, not another concurrent RunWriter.
When actor dies, broker retains immutable pending record+bytes; cold writer recovery
validates/commits it once. This broker/B/journal delivery seam is required precode
closure, NOT already implemented or implied by Job support.

9. Explicit unresolved trust/deployment choice — source blocker
Jobs constrain ordinary CreateProcess lineage; they are not a security sandbox
against identical unrestricted principal, WMI/service-created process or arbitrary
remote effect. Unnamed handles/noninheritance/DACL do not prevent malicious same-
user code opening broker/duplicating handles/changing ACL or spoofing private files.
Choice U1 trusted cooperative targets: prove native closure ONLY for declared
ordinary lineage under this explicit trust profile; classify unmediated outside-
Job effects external Unknown. This is useful positive execution evidence, but
CANNOT retire an original requirement demanding hostile same-user confinement.
Choice U2 separate protected broker+target security profile (account/restricted
capability/token/DACL/manager policy) with actual nonmigration/nonduplication proof:
requires a separate deployment/credential compatibility design and authorization;
no silently changed accepted credential/token/session in this draft.
Maintainer MUST choose applicability against original scope before native coverage
can be accepted. U1 is proposed first executable fixture profile, not a settled
product security contract or approval to weaken requirements. Broker auth protects
against accidental/stale/wrong peer within U1; it does not pretend isolate U2.
Native object closure never settles undeclared arbitrary remote work. Tracked
external adapters still require exact original occurrence/terminal evidence.
