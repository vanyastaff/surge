Architecture and ownership
1. Dependency direction remains coherent. Core owns pure route declarations, planned event and pending-phase domain data. ACP registry carries host-declared route metadata without a persistence dependency. Persistence owns SQL admission ordering, sealed source receipts, recovery binding and the exclusive preparation capability. Orchestrator resolves profiles, actual launch recipes and private HMAC fingerprints; its RecipeAdmissionBridge decorates the raw facade instead of putting SQL inside the ACP transport. Daemon coordinates the existing Git preparation and Engine freeze. The new nix/HMAC dependencies are workspace-managed; no new framework or upward dependency is introduced.

2. Existing capabilities are reused. A selection describes persisted state; it is not an RPC permit (recovery_cycles/predispatch.rs:7-35). Selected launches still reserve/admit/spend the existing quota opening handoff. The all-skipped case has its own planned proof rather than manufacturing a provider error/session. Reactive typed-429 receipt recording remains intact. Actual logical stage invocation and actual provider invocation are separated in run_task.rs selection and stage/agent.rs:1043-1058. This is a bounded extension of the existing recovery ownership model, not a second competing scheduler.

3. Public preparation shape is appropriately narrow. StartPreparation (start_preparation.rs:8) has private fields, no Clone or Serde, carries the original workspace and holds a private OS lock. Its two observation getters confer no provider authority. finalize consumes the capability, verifies the exact request and saved snapshot, then atomically consumes the row, reserves the ordinary attempt and stores the original operation receipt (:34-95). There is no callback-based transaction API, premature Prepared acknowledgment, serialized lock authority or public generic filesystem utility. The small domain-private OS lock implementation is a justified bounded duplication of existing secure descriptor patterns: importing the upper orchestrator key helper into persistence would reverse the dependency direction.

Transactional and worker lifetime boundaries
4. begin_start_preparation checks replay before filesystem work and again in its short transaction. Held lock identity, persisted identity, exact item/version/accepted state and snapshot bind preparation to the current original owner. The generic mutate/reserve paths enforce the preparing-row fence; lifecycle reclamation first acquires the same secured lock outside SQL. A replacement inode or a PID/elapsed-time assertion cannot prove the old owner died. Finalization checks the full snapshot, including controls, and rolls back consumption if ordinary reservation fails. Concurrent original operation replay returns its stored receipt rather than grant another launch.

5. daemon/work_items.rs:233-264 moves the guard into spawn_blocking across Git reconciliation, configuration discovery and actual-workspace freeze.
