# Owned ordinary flow normalization: revised pre-code plan

Owning maintainer verdict: ACCEPTABLE for the bounded design below, subject to the same independent Phase 2.5 reviewers. This is the NEXT unit, not acceptance of the current pre-dispatch slice or T12 completion. No repository edits or Cargo checks accompany this plan.

## Current API facts

- CLI engine.rs Run has no operation identity today; run_command reads the graph at line 180, checks workspace existence and discovers SurgeConfig before choosing the daemon facade. Therefore retry cannot currently precede missing-file/config checks.
- server.rs StartRun uses caller run_id and an in-memory PendingStarts map. ResumeRun calls generic tracking.resume with caller worktree_path; StopRun relies on admission.cancel_queued then generic facade.stop_run. None alone is durable owned-flow dispatch/cancellation authority.
- WorkItemRequirements::new requires nonempty text and criteria. Its hash is serde_json of its original text/criteria representation. WorkItemContext::prompt decorates those requirements. Flow prompt must not pass through this constructor.
- engine/work_items.rs pinned hydrates immutable accepted context, overwrites initial_prompt with context.prompt, and validate_resume verifies graph, context, prompt artifacts and startup config.
- validate_claim permits Reserved/Launched/Attention/Suspended; it is not an exact pending-start authorization predicate.
- StartPreparation owns an existing WorkItem's per-item OS lock, frozen snapshot and finalize capability. Its workspace_prepared bit comes from a genuine earlier launch acknowledgment. It cannot provision a nonexistent accepted item.
- secrets.rs is plaintext, mutable SQL storage protected only by filesystem permissions. Its comments explicitly say Telegram no longer uses it; TelegramCredentials is runtime-only and redacted, with environment references. Neither is an immutable secure-input snapshot vault. Do not label that SQL table encrypted or sufficient permission enforcement.
- McpServerRef contains exact command, ordered args, env map, tools, timeout, restart policy and sandbox. Persisting EngineRunConfig wholesale or RunStarted.config.mcp_servers exposes those args/env in public registry/journal projections.

## 1. Stable submit and replay, independent of present rotation settings

All ordinary CLI flow submissions use one owner-aware daemon endpoint before reading current rotation configuration, even if rotation has since been disabled. Do not select the endpoint from mutable current capacity settings. Existing local graph-engine API remains explicit in-process infrastructure; it must not impersonate durable CLI ownership.

OwnedFlowStart has operation_id, source_project, FlowInput, OwnedFlowRunConfig and WorkspaceRequest. Host allocates run/item/workspace-owner IDs; callers never obtain SQL preparation permission or substitute a launch claim. Exact canonical request identity includes every allowed explicit field, variants, sorted map keys and preserved list order.

FlowInput is Inline { graph }, ProjectFile { locator }, or Template { key }. CLI adds --operation-id for retry and sends ProjectFile/Template intent before local flow reads/discovery. A default command creates a fresh operation; same path alone never means replay. Inline changed graph conflicts. A locator retry intentionally reuses the first captured graph even if its file/template is missing or changed. Changing the locator or any explicit DTO input conflicts.

Locator construction is lexical: anchor relative paths to the explicitly transmitted absolute source_project base, never daemon cwd. Normalize dot components and reject escaping ProjectFile locators; no filesystem canonicalization/existence check before replay. First resolution validates the real source project and locator scope, opens the target with held-descriptor no-follow/regular/bounded-read checks, and captures the parsed graph once. Symlink escape/replacement must fail closed. The resolved graph/base snapshot is immutable thereafter; no post-snapshot reopen of the locator.

Legacy StartRun keeps its caller RunId contract. It must explicitly reject an owned-flow submission requiring normalization and direct callers to OwnedFlowStart, rather than allocate a different run silently. If legacy calls address an already owned run, collide/refuse using the durable run ownership lookup. Do not expand the legacy request into a new owner using unrelated IDs. CLI uses the new endpoint; wire clients get an explicit error, not hidden replacement.

OwnedFlowRunConfig denies unknown fields and excludes agent_registry, memory_store_path, supplied quota policy/pins and host-derived memory claims. Fallible EngineRunConfig conversion rejects excluded non-default fields. It preserves all allowed explicit knobs, initial_prompt, seeds and full MCP inputs. Construct it before host seeding. Optional overrides distinguish absent host defaults from explicitly requested unlimited budget/default-valued settings. Canonical identity includes the exact override representation. Derived host seeds/defaults are a separate immutable startup snapshot.

## 2. Typed accepted origin without old hash changes

Introduce validated FlowOrigin/AcceptedFlowContract with exact graph hash and exact raw prompt, bounded but permitting empty and whitespace-only values. Constructor/deserializer validate the graph payload/hash relation at acceptance; persisted host hydration rechecks it. No trim, synthesized criteria, task title or prompt decoration. A graph hash alone from untrusted JSON is insufficient.

Represent accepted origin as a backward-compatible discriminated flow extension to revision/context storage. Legacy requirement records retain their exact existing serialization and hash algorithm, covered by golden byte/hash fixtures. The new flow branch has its own domain-separated hash. WorkItemContext construction, requirements retrieval, pinned, startup artifact materialization and resume validation all branch on typed origin; no adapter that forces flow data into WorkItemRequirements.

Flow context.prompt returns the accepted raw prompt exactly. Frozen config and startup RunStarted initial_prompt match it. Empty prompt follows the engine's existing no-user_prompt-artifact behavior; startup validation must not require a nonexistent empty prompt artifact. Nonempty and whitespace-only prompts preserve exact bytes and validate their actual artifact. Accepted contract artifact is separately authenticated for every flow origin.

## 3. Provisional ownership before atomic acceptance

Add request-scoped provisional rows, not accepted task records. First-body identity and allocated run/item/workspace-owner IDs are immutable once recorded. Graph/base/workspace/lock identity are write-once snapshot fields; never replace these on abandonment or death. State/lease token may change only after obtaining the same stable OS lock. Keep an operation identity tombstone even for abandoned preparation so a different body cannot reuse the operation ID.

States distinguish Allocated, Snapshotted, Preparing, Accepted, Abandoned/Attention. Before snapshot, retry may complete the first resolution under the same IDs; once snapshot exists, retry uses only that captured graph/base/workspace. If captured source/base is unavailable, attention/refusal preserves the original identity; do not substitute current HEAD or another graph.

Private OwnedFlowPreparation guard holds the stable request lock throughout Git reconciliation, private input capture and actual-cwd freeze. Reuse PreparationLock through visibility restricted to crate::work_items and a private typed Task/FlowOperation key. No public generic filesystem API. Preparation SQL transactions remain short; Git checkout, auth reads and all async waits occur outside DB under the guard. Cancellation cannot release the guard before its blocking worker ends.

The provisional row is the durable original creation ownership intent for task_workspace::prepare. It is not provider permission, generic Reserved wake authority or a launch intent. Dirty source on first resolution fails without changes to files/index/HEAD. Arbitrary explicit worktree adoption is rejected. Registered workspace identity/base is verified on retry, never reset/adopted. A failed/dead preparation preserves its directory and first snapshot; no automatic destructive cleanup. Any later cleanup must prove the original owner and no accepted attempt/active guard, and remain outside this minimal unit.

Final short IMMEDIATE transaction rechecks full request/snapshot/lock identity, run-ID collisions and guard token. It atomically creates graph-backed item + accepted revision + immutable attempt with the host RunId + explicit owned-flow launch intent + operation result, and consumes provisional preparation. Private input objects are already durably published before their references are accepted. Crash-created unreferenced private objects grant no authority.

## 4. Complete MCP fidelity with bounded private permitted inputs

Do not reuse mutable plaintext secrets.set_secret as an immutable vault. Use a bounded operation-owned private input object for explicit MCP command/args/env and corresponding exact frozen transport inputs. Descriptor-checked host-owned 0700 directory and 0600 regular object, no-follow/no-clobber publication, file and directory durable sync before acceptance, immutable reference and authenticated fingerprint, fail closed on ownership/ACL/platform capability errors. This is local plaintext permitted-input storage, not encryption. It is justified by explicit user submission of those MCP inputs, not permission to capture inherited provider credentials.

Persist only opaque private-input references and redacted/nonsecret MCP manifest in public attempt/config/receipts/journal. Engine hydration resolves that immutable object for actual MCP startup; startup validation verifies its identity plus public tool whitelist, sandbox, timeout and restart policy. Add a flow-specific startup manifest/reference event rather than writing raw transport args/env into RunStarted.config.mcp_servers. Preserve exact actual transport command/ordered args/env in runtime memory; never silently drop them or substitute empty MCP configuration. Existing non-flow legacy serialization is unchanged. Missing/corrupt private input gives attention before MCP/provider effects, not reconstructed defaults.

### Bound authenticated effective MCP inputs and cold-resume precedence

Actual engine/engine.rs resume currently hydrates task config via pinned, then overwrites mcp_servers from the public replayed RunStarted config. resolve_run_mcp_registry additionally interprets an empty list as permission to use the current global registry. Both branches MUST distinguish authenticated owned-flow inputs from legacy behavior. For an owned flow, authenticated private hydration is authoritative on initial start, actual cold resume and capacity wake: never clone the public startup list over it and never consult current global/project MCP configuration to replace it. Budget/other public projections remain independently checked against the immutable accepted startup inputs.

The DTO uses an explicit MCP selection: HostDefault or Explicit(Vec<McpServerRef>). Explicit empty means no MCP; it is not absent/default. On FIRST snapshot only, resolve HostDefault using the host's documented existing project/global precedence; materialize the final effective list once, including an empty list. Persist the selection and effective list under the immutable snapshot. with_project_context_seed must not fill Explicit(empty) or alter a previously resolved owned-flow list. Changes to host/project defaults on replay/restart cannot change the frozen list. Full user-provided command, ordered arguments and environment values remain exact; no sanitizer replaces runtime values.

Use a validated, host-only AuthenticatedOwnedFlowInputs capability produced by accepted-attempt hydration, not a caller bool such as no_global_fallback. It carries a Frozen MCP list, including empty. Both initial and resume resolve_run_mcp_registry call sites select this authoritative list when that capability is present; only legacy paths retain the old empty-list fallback. The capability is not serializable and is excluded from wire DTO conversion, so generic caller JSON cannot authorize private hydration. Recheck its exact run/binding/workspace association before MCP initialization.

Each private object and its authenticated reference bind the domain-separated purpose and schema version, operation ID, canonical request digest, retained item/run/workspace creation-owner identity, server identity and ordered server index, exact frozen public MCP manifest, private transport bytes and immutable object reference. Authenticate the ordered whole-list envelope as well: deletion, insertion or permutation cannot produce a different valid effective list, and Explicit(empty) has an authenticated empty envelope. Server identity includes its accepted name; index and name are not interchangeable. The public manifest binds sandbox, allowed-tools semantics (including None versus empty), timeout, restart policy and all nonsecret presentation fields. Private-byte authentication covers exact command/path, ordered args and env map. No plain body/hash is exposed in receipts.

Acceptance persists this authenticated envelope/reference in the immutable attempt startup inputs. The flow-specific startup journal event records the same manifest/reference, binding and envelope identity. At initial launch, cold resume and wake, validate private bytes, envelope, accepted attempt and startup journal together BEFORE constructing MCP registry or any executable writer. A foreign operation/run/workspace/server object, reordered/transplanted entry, edited sandbox/tool whitelist or mismatched public manifest is attention/refusal before effects, even if that object is otherwise valid under the same host key. Do not regard a correct standalone content hash as ownership proof.

Private objects may be published before acceptance but gain no launch authority until the accepted attempt references them. HMAC key loading during hydration is existing-key-only and fail closed: missing, corrupt or substituted key never creates a replacement, recaptures input or falls back to current defaults. Initial key creation is restricted to a verified empty private-input namespace with no existing provisional/accepted authenticated references; once an identity exists, loss is an explicit recovery-required condition. Key lifecycle needs the existing hardened publication/ownership algorithm and independent security review, not a claimed encrypted vault. Inherited provider auth remains live and excluded from these explicit permitted MCP inputs.

Never snapshot inherited provider env/auth files into private inputs, registry, journal or evidence. Continue live source revalidation and HMAC pins only for configured provider auth. Debug/Display/errors/receipt projections omit raw request/config/transport values; use bounded identifiers and reason codes. Canonical identities containing permitted secrets use a host-authenticated digest, not publicly expose raw canonical bodies or secret-derived plain hashes. Public criteria/prompt artifacts remain user-authored content, not a secret-handling claim.

The new private store requires its security capability on the host platform; unsupported sensitive-input capture rejects explicitly, with no insecure fallback. Ordinary requests with no private MCP transport values must not acquire a new Unix-only requirement. Windows ordinary execution remains supported by existing paths; complete Windows private-input ACL capability, if unavailable, stays an explicit unclosed platform case. No new encrypted-vault architecture or user approval is inferred.

## 5. Owned lifecycle and cold startup

Durable intent states Pending/Started/Cancelled/Attention, with exact run/binding/generation and control fence. At effect time require Pending + active Reserved + current accepted revision/workspace + no archive + permitting control + genuine launch claim. validate_claim alone is insufficient. Final startup/admission dispatch rechecks this predicate, including a cancellation that races queue draining.

Extend legacy StopRun/ResumeRun handlers with durable owned-run lookup BEFORE generic admission/facade branches. Owned StopRun transactionally cancels Pending intent even if the in-memory queue is empty, fences later dispatch, and uses existing task controls for live attempts. Owned ResumeRun routes through durable generation-fenced task continuation and retained workspace; reject a supplied alternate worktree. It does not call generic resume using caller paths or create a new attempt. Status/replay remain available after current config changes.

Queued cancellation uses durable intent as source of truth, admission cancellation only as a secondary in-memory optimization. Invalid-control/Attention/Suspended claim never authorizes a pending first launch. Existing journal history requires authenticated startup hydration and continuation/attention, never another first start. Cold reconciliation of journal-less Reserved is enabled ONLY by exact explicit pending owned-flow intent. Generic Reserved stays inert. Crash after startup commit before intent ACK recognizes the same authenticated run instead of duplicating startup/provider effects.
