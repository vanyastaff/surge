# 06 — Context pack под бюджет, с распиской и порядком по доверию

**Требования:** R24, R25, R26, R20
**Blocked by:** 05
**Зона:** `crates/surge-core/src/context_pack.rs` · `crates/surge-orchestrator/src/project_context.rs`
**Волна:** 3
**Status:** ready

## Что должно заработать

Контекст ноды собирается под жёсткий токен-бюджет: прямое доказательство идёт раньше слабого припоминания, а не «сколько влезло». Сборка возвращает расписку — что взято, что выкинуто и почему, — и расписка уходит в event log, поэтому в replay видно, что именно агент знал и чего не знал.

## Из брифа, дословно

> «**Context packs under a hard token budget**, with a receipt recording what was selected, what was dropped, and why»
> «so a node's context can order direct evidence ahead of low-trust recall»
> «a run that used memory can be replayed to show exactly which entries entered which node's context, and why each was chosen»

## Разделы спецификации

Истории 23–24, 44. Решения §8, §23. Границы: `surge-core::context_pack`. Швы §1 и §2.

## Критерии приёмки

- [ ] `ContextPack::build(claims, budget) -> (ContextPack, PackReceipt)` — чистая функция, без I/O
- [ ] Пакет **никогда** не превышает бюджет; бюджет — ключ в `surge.toml` с консервативным дефолтом
- [ ] Порядок отбора задаётся `Confidence`: `verified` → `name_matched` → `asserted`; это часть контракта, а не скрытая деталь
- [ ] `PackReceipt{selected,dropped,reason,budget,used}` пишется в event log
- [ ] Replay показывает расписку для каждой ноды
- [ ] Property-тест: сумма отобранного ≤ бюджета при любом входе

**Сделано и доказано достижимым:**
`ContextPack::build(claims, budget) -> (ContextPack, PackReceipt)` — чистая, без I/O.
Бюджет не превышается **при любом входе** (property-тест). Порядок по `Confidence` —
задокументированный контракт модуля, и тест доказывает, что доверенное утверждение
побеждает более «выгодное» по бюджету, но менее доверенное.

Достижимость доказана **боевым путём**, а не вызовом: тест сеет настоящее
`MemoryStore` на диске (через ограниченную подмену `$HOME`) и гонит через
`with_project_context_seed` — ту самую точку, куда сходятся все четыре входа запуска
рана.

## ⚠️ Сужение, которое надо признать сужением

Чтобы остаться в зоне, исполнитель вложил пакет утверждений в **существующий
run-level seed** проектной памяти, а не сделал его **по-нодным**.

Спецификация просит другого: §8 говорит, что расписка уходит в event log и оттуда в
Run Report, а История 24 — что replay показывает расписку **для каждой ноды**.
Run-level пакет отвечает на вопрос «что знал ран», а требование про «почему **эта
нода** этого не знала».

Исполнитель это отметил сам и предложил вернуться, если тасками 07/09 понадобится
по-нодная гранулярность. **Она понадобится**: таск 09 (Run Report) перечисляет
расписки памяти среди девяти разделов отчёта.

→ **Условия второго захода** (запускать после коммита таска 17, когда `run_event.rs`
освободится):
- [ ] `PackReceipt` пишется в event log
- [ ] Replay показывает расписку **для каждой ноды**, а не одну на ран
- [ ] Пакет собирается **на ноду**, а не на ран — либо в спецификации явно записано,
      почему run-level достаточно, и История 24 переформулирована. Молчаливое
      сужение недопустимо: это ровно тот класс, который прогон ловит с волны 1

## Условие, добавленное к второму заходу (2026-09-06) — герметичность тестов

Найдено при починке таска 07, подтверждено чтением. Файл `project_context.rs` — твоя
зона, поэтому чинишь ты.

`with_project_context_seed_threshold_tests` — три теста (`unset_thresholds_are_filled_from_surge_config`,
`explicit_caller_value_is_not_clobbered_by_surge_config`,
`explicit_default_valued_setting_is_not_mistaken_for_unset`, строки **1627, 1670, 1710**)
зовут `with_project_context_seed(...)` **без** обёртки `with_home`, которая есть в том же
файле и используется соседними тестами (1549, 1561, 1589).

`EngineRunConfig::default().project_memory.is_none()`, поэтому цепочка
`merged_project_memory_seed` → `load_memory_claims_seed` (:647) доходит до
`MemoryStore::default_path()` (:648) и резолвит **настоящий `$HOME`**.

**Мутации нет** — путь защищён `if !store_path.exists() { return None; }`. Но если у
разработчика стор существует, тесты вызывают `MemoryStore::open` на **реальном файле**,
а `open` выполняет `create_dir_all` и `initialize_schema()` (`memory/store.rs:30-42`), и
затем засеиваются его настоящими claim'ами. Исход теста зависит от состояния машины —
на чистой машине он проходит по одной ветке, у разработчика с накопленным стором по другой.

**Чинить `with_home` не надо** — таск 07 доказал, что подмена `$HOME` здесь
несостоятельна в принципе (аудит `unsafe`: вендоренный libgit2 читает `"HOME"` голым
`getenv` мимо `ENV_LOCK`). Правильная починка уже доступна: таск 07 завёл
`EngineRunConfig::memory_store_path: Option<PathBuf>` (`engine/config.rs`, `#[serde(default)]`,
в персистентный `RunConfig` намеренно не попадает). Передавай путь **явно**, как это
теперь делает `memory_writeback_test.rs`.

Если по ходу окажется, что синхронные `with_home` в этом файле тоже стоит убрать тем же
полем — убирай, это снимет ещё три `unsafe`. Но не обязательно: аудит признал их
приемлемыми для синхронного случая.
