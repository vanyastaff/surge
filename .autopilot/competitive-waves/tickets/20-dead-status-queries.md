# 20 — Мёртвые запросы по строке статуса и хрупкий листинг ранов

**Требования:** нет — найдено попутно при проектировании таска 12, вне брифа
**Волна:** после прогона
**Status:** deferred — **решение о запуске принимает пользователь**

## 1. `snapshot_active_runs` не возвращает ничего уже сегодня

`crates/surge-persistence/src/runs/storage.rs:365-370` фильтрует
`status IN ('Running','Bootstrapping')`, а `RunStatus::as_str()`
(`crates/surge-core/src/run_status.rs:35-36`) пишет `"running"` / `"bootstrapping"`.

SQLite сравнивает строки с учётом регистра → **запрос пуст всегда**. Значит дедуп,
который на нём построен, не работает и не работал.

Найдено дважды независимо: `harsh-critic` и `chief-architect` при проектировании таска 12.

→ Правило: **никогда не писать литерал статуса в SQL.** Привязывать `RunStatus::as_str()`.
Заодно проверить остальные запросы, сравнивающие статус со строкой.

## 2. Одна битая строка валит весь листинг ранов

`row_to_summary` мапит ошибку разбора в `FromSqlConversionFailure`
(`crates/surge-persistence/src/runs/registry.rs:181-185`), а `list_runs` делает
`.collect::<rusqlite::Result<Vec<_>>>()?` (`:146`).

Следствие: **одна нечитаемая строка делает недоступным весь список**, а не «один ран
выглядит странно». Та же строка убивает `plan_recovery`, который начинается с
`list_runs` (`crates/surge-daemon/src/recovery.rs:235`).

Сегодня это достижимо уже без всякого нового статуса — битым ULID в колонке `id`
(`registry.rs:177-180`).

→ Условие, если браться: пропускать нечитаемую строку с предупреждением **и видимым
счётчиком**. Молча ронять раны нельзя — это ровно ловушка «тихо потерянный класс
входов», записанная в `interfaces.md` и в память проекта.
