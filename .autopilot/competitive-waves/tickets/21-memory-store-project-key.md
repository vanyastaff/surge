# 21 — Стор памяти глобален, а локаторы проектно-относительны

**Требования:** нет — найдено ревью таска 08 (перезапуск), вне брифа
**Волна:** после прогона
**Status:** done — разрешено в пользу варианта 1 (ключ проекта в провенансе). `Provenance.project_root: Option<PathBuf>` — аддитивное `#[serde(default)]` поле без бампа event-схемы; схема стора v2→v3 добавляет nullable-колонку (шаг идемпотентен: v1→v2 создаёт таблицу уже с колонкой). Write-back прикрепляет корень проекта run'а; аудит резолвит относительные локаторы против **собственного** корня claim'а, откатываясь на прежний якорь для старых записей. Тест мутационно-доказуем: без записи корня claim из проекта A, аудируемый из B, даёт ложный `source_missing`. Кросс-проектная память сохранена (вариант 2 отвергнут).

## Что не сходится

Стор памяти **один на машину**: `$SURGE_HOME/memory.db` (`MemoryStore::default_path()`).
А файловые локаторы в `Provenance::source` — **проектно-относительные**, и якорь
разрешения — репозиторий, объемлющий текущий каталог
(`common::project_root` → `GitManager::discover()` → `Repository::discover(".")`,
`worktree.rs:107-111`).

**В самом claim'е не записано, к какому проекту он относится.**

## Следствие, замеренное

Claim, снятый в проекте A и проверяемый из проекта B, разрешается **не туда**. Аудит,
запущенный вне какого-либо git-репозитория, даёт `plain.md → source_missing` — то есть
**ложное предложение удалить запись** о файле, который на месте.

Направление ошибки худшее из возможных: инструмент, чей выход — «предложить удалить»,
предлагает удалить по причине, которой нет.

## Почему это не чинилось в таске 08

Таск 08 чинил другое — разрешение относительно **CWD процесса** вместо корня проекта, и
это закрыто: классификация внутри одного проекта теперь стабильна, побайтово одинаковый
JSON из корня и из вложенного каталога. Выбранный якорь — **лучший доступный** без
изменения формы модели.

Лучше без ключа проекта на claim'е не сделать.

## Если браться

Варианты, не проработанные:
- ключ проекта в `Provenance` (аддитивное опциональное поле → бампа не требует, но нужен
  ответ, что делать с уже накопленными claim'ами без ключа);
- стор на проект вместо глобального (ломает замысел «память переносится между проектами»,
  ради которого он и глобальный);
- локаторы абсолютными путями (ломает переносимость).

Первый шаг — решить, **должна ли** память быть кросс-проектной. Сегодня она такова по
факту хранения, но не по разрешению ссылок, и это внутреннее противоречие формы, а не
дефект реализации.
