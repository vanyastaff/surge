## Minimal live abstraction, not unused types
A `ManagedMcpBackend` injected into actual host MCP spawn needs prepare/open_recovery, launch exact program/args/cwd/env with stdio, revoke admission, settle/probe exact domain. Typed retained handle owns process containment. Backend identity originates from host-established kernel/manager capability, not request payload. Broker is actual external-effect execution boundary with durable admission-before-dispatch, request dedup identity and settlement receipts; require denial of direct network/host IPC/file capabilities outside allowed local workspace or the broker is bypassable.

A backend trait alone does not implement a backend. For Linux a real provisioned cgroup-v2+namespace containment path can be possible only with preexec membership and inaccessible migration/control permissions; namespace/process mechanisms must prevent descendant escape. On macOS existing GroupOnly evidence has no equivalent guarantee: require a concrete managed VM/container service or verified restrictive platform policy rather than branding process_group as managed. Unsupported backend availability must refuse opt-in before target starts, without weakening default behavior.

## Hazards
Current `WriterContainer.coverage=CoveredDomain` is publicly constructible and structurally serializable; trusting that enum without a host capability issuer is fake proof. Domain empty never settles remote effects already dispatched. An unrestricted MCP can bypass an effect broker, so backend network/IPC restrictions are mandatory. Process observation after spawn races target effects. Cwd/env/executable fidelity cannot be replaced by a demo server. Secret-bearing requests/config must remain private and redacted in public journal/projection. Managed retries require exact retained domain identity, not merely same server name.
