## Smallest full backend slice recommendation
Implement Linux managed local-only MCP first, on a demonstrated delegated host. Runtime preflight requires cgroup-v2 domain, enforced no migration/control capability, actual supported syscall/namespace/FS policy, and host-owned launch/recovery owner. Use race-free placement before server exec (clone3 CLONE_INTO_CGROUP or trusted stopped launcher handshake where no untrusted instruction executes). Use FD-relative cgroup identity plus boot/mount identity and inode/nonce validation, not cgroup pathname/PID. Domain stop uses actual cgroup kill, then populated=0 under revoked admission, with descendants/subgroups covered. A namespace alone is not containment: cgroup documentation explicitly permits migration when outside permissions exist.

Effect proof for the first slice is enforced zero external capability, not server attestation: deny all egress sockets/IPC to outside services; clean inherited descriptors; immutable/runtime read mounts; generation-private local write staging only; no host journal/common Git/provider-state/runtime sockets exposed. No host filesystems with uncontrolled remote or special-device side effects. Drop privilege/capabilities and enforce no_new_privs/inherited seccomp; never allow restoring namespace/control privileges. Thus proof two is established enforced LocalOnly policy plus drained host-effect ledger (empty for direct remote effects). Future remote-capable servers need explicit host-mediated idempotent effects/settlement receipts. Ordinary MCP tools response and cancel are insufficient. Unsupported policy fails before spawn.

MCP sandbox intent is distinct from actual managed policy. Never set local_effects=true or CoveredDomain from config/server labels. Issuer creates proof only after backend establishment and policy validation. Closure requires both proof outcomes for exact writer/invocation/domain/generation. Existing native mode stays GroupOnly+local_effects=false, with RecoveryRequired where unresolved.

## Full accepted contract: broker and external ambiguity remain mandatory
The local-only Linux capability is an initial executable slice, not the complete goal. Full managed MCP requires host-effect broker/journal: generation/revision/base/effect IDs validated under admission lock before dispatch; durable intent before actual mutation/network request; idempotent receipt/result evidence; drain or explicit unknown on timeout/host crash. Domain emptiness cannot resolve remote accepted-but-response-lost work. Remote service must support idempotency plus authenticated status/settlement capability or that effect remains Unknown and blocks closure. A successful request response proves only its specified effect contract, not unrelated child-created work. No synthetic receipt from EOF/cancel. Reuse OwnedFlowEffectFence and RunEventRecorder, but neither current check-before-effect nor writer-level local_effects flag is already a transactional broker ledger. Freeze broker policy/version and service capability identity in accepted managed launch; receipts bind exact writer, operation generation and payload hash without secret material.

Guest paths/exact manifest: accepted command/args/env/cwd are opaque authenticated transport. Guest runtime/image and immutable path-map contract must be frozen before acceptance; mounts map exact approved paths and contain alias/FD escapes. Host /usr/bin/python macOS cannot silently become Linux guest python under same executable identity claim. Preserve existing wire oracle; compatible macOS guest or explicit accepted launch contract establishes actual binary/path identity. Missing guest interpreter/image/pinned mapping refuses without alternate spawn. Cold resume validates image/runtime instance/guest boot/storage volume/path map/policy hash, never substitutes current setup.

Candidate ADR acceptance scenarios: (1) journal unavailable prevents server instructions and effects; (2) setsid/doublefork cannot escape actual domain; (3) host crash with live domain makes zero restore/MCP calls; (4) verified domain empty + broker fully settled creates exact durable closure and automatic original-transport resume; (5) verified empty domain with remote request ambiguity remains Attention and zero replay; (6) service idempotency settlement proves exact effect without duplicate request, then admits automatic recovery; (7) stale generation broker action refused under lock; (8) guest image/path map/volume/instance/boot mismatch refuses; (9) runtime name reused cannot inherit evidence; (10) public snapshot excludes credentials/private command/env; (11) unchanged native unknown refusal and all original accepted tests retained. These are mandatory goal acceptance, not criteria retired by initial local-only positive.
